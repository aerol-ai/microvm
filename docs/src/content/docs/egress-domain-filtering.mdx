title: Allow only some websites
description: Let a sandbox reach only the websites you name, like pypi.org or *.github.com, and see what it was refused.
---

import { Tabs, TabItem } from '@astrojs/starlight/components';

An agent that installs packages or calls one API rarely needs the whole internet. With an allow list of website names, a sandbox can reach `pypi.org` or `*.githubusercontent.com` and nothing else.

You write names, not IP addresses. AerolVM looks up their addresses through DNS (the system that turns names into IP addresses). It follows the addresses as they change and checks the name on every connection. Many sites share the same addresses on a CDN (a service that hosts many sites together). The name check means a sandbox cannot reach another site just because it shares an address with an allowed one.

This page uses the same `networkAllowOut` list as [Block or allow the internet](/network-isolation/), which covers IP address ranges. One list can mix names and ranges. To reuse a list across sandboxes, see [Reusable allow lists](/egress-profiles-and-learn-mode/). To allow only some requests to a site, see [Rules and inspection](/egress-rules-and-inspection/).

## Allow a few websites

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'python:3.12',
      networkAllowOut: ['pypi.org', '*.pythonhosted.org', 'github.com:22'],
    })
    ```
  </TabItem>
  <TabItem label="Python">

  </TabItem>
  <TabItem label="Go">

  </TabItem>
  <TabItem label="Rust">

  <TabItem label="Java">

    ```java
    );
    ```
  </TabItem>
</Tabs>

Now `pip install requests` works, and `curl https://example.com` fails at once with a message that names the host. Nothing else changes inside the sandbox. Programs look up names and connect the usual way.

### What each entry allows

| Entry | Allows |
|---|---|
| `pypi.org` | `pypi.org` on ports 80 and 443 (HTTP and HTTPS) |
| `*.pythonhosted.org` | every name under `pythonhosted.org` on ports 80 and 443, but not `pythonhosted.org` itself |
| `github.com:22` | `github.com` on port 22 only |
| `10.20.0.0/16` | that IP address range, on any port |

- Names ignore upper and lower case, and a trailing dot.
- A list holds up to 64 names, plus any number of address ranges.
- To allow a name and everything under it, list both: `example.com` and `*.example.com`.
- `networkDenyOut` takes address ranges only. When you set both lists, the allow list wins. Then a match in the deny list is dropped, and anything else is allowed. Add `networkDenyOut: ['0.0.0.0/0']` to make the allow list the only way out.

### What the sandbox sees when it is refused

| What the sandbox tries | What happens |
|---|---|
| Look up a name that is not allowed | The DNS lookup (the step that turns a name into an address) answers `NXDOMAIN`, meaning "no such name". An extra note in the answer reads `aerolvm egress policy: <name> not allowed`. |
| Open HTTPS to a site that is not allowed | The connection fails in its first step with an `access_denied` alert. The check reads the site name the program sends when it opens HTTPS. So a connection to an allowed address that asks for a different site is refused too. |
| Send an HTTP request to a site that is not allowed | It gets a `403` response. The body names the host and the rule that decided. |
| Anything else, such as a raw IP address or another port | The connection is closed at once, unless an address range or `host:port` entry allows it. |

Each of these fails fast with a reason. An agent can stop retrying and ask for access, instead of waiting for a timeout.

## See what was refused

Every refusal goes into the sandbox's audit log, with the destination and the reason. Read it with `audit`, filtered to network events:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const page = await sandbox.audit({ kind: 'egress' })
    for (const event of page.events) {
      if (event.result === 'failure') {
        console.log(`${event.time} ${event.destination} refused: ${event.reason}`)
      }
    }
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    page = sandbox.audit({'kind': 'egress'})
    for event in page['events']:
        if event['result'] == 'failure':
            print(f"{event['time']} {event.get('destination')} refused: {event.get('reason')}")
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    page, err := sandbox.Audit(ctx, sdktypes.AuditOptions{Kind: "egress"})
    if err != nil {
        return err
    }
    for _, event := range page.Events {
        if event.Result == "failure" {
            fmt.Printf("%s %s refused: %s\n", event.Time, event.Destination, event.Reason)
        }
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let page = sandbox.audit(AuditOptions {
        kind: Some("egress".to_string()),
        ..Default::default()
    })?;
    for event in page.events.iter().filter(|e| e.result == "failure") {
        println!("{} {:?} refused: {:?}", event.time, event.destination, event.reason);
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    AuditPage page = sandbox.audit(new AuditOptions().setKind("egress"));
    for (AuditEvent event : page.events) {
        if ("failure".equals(event.result)) {
            System.out.println(event.time + " " + event.destination + " refused: " + event.reason);
        }
    }
    ```
  </TabItem>
</Tabs>

The reasons you can see:

| Reason | What happened |
|---|---|
| `dns_not_allowed` | A name lookup for a name that no entry covers. |
| `host_not_allowed` | An HTTP request (or a WASM or V8 isolate connection) to a name that no entry covers. |
| `sni_not_allowed` | An HTTPS connection to a name that no entry covers. |
| `no_sni` | An HTTPS connection that sent no site name, to an address that no range allows. |
| `ip_not_allowed` | A direct connection to an address that no range allows (WASM, V8 isolate). |
| `sni_mismatch` | A WASM sandbox connected to an allowed name, but its HTTPS asked for a different one. |
| `blocked_ip` | An allowed name pointed to a private, loopback (`127.0.0.1`) or cloud metadata address. |
| `firewall_reject` | Another port or protocol, refused by the server's firewall. |
| `dns_rate_limited` | The sandbox made too many name lookups. |
| `conn_cap` | The sandbox has too many connections open through the filter. |
| `upstream_proxy_unavailable` | The operator's outbound proxy could not be reached (private networks only). |

The log comes a page at a time. Pass `nextCursor` back as `cursor` to read older pages.

## Check the filter's state

For Docker, containerd and gVisor sandboxes, a separate filter service on each server does the name checks. (containerd is another container engine, like Docker.) It is called the egress gateway. If it is down, sandboxes that use names lose all outbound traffic instead of running unfiltered. `get` tells you which state a sandbox is in:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const current = await client.get(sandbox.id)
    console.log(current.egressStatus) // "active", "held" or "unavailable"
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    current = client.get(sandbox.id)
    print(getattr(current, 'egressStatus', None))  # "active", "held" or "unavailable"
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    current, err := client.Get(ctx, sandbox.ID)
    if err != nil {
        return err
    }
    fmt.Println(current.EgressStatus) // "active", "held" or "unavailable"
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let current = client.get(&sandbox.data.id)?;
    println!("{:?}", current.data.egress_status); // "active", "held" or "unavailable"
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox current = client.get(sandbox.id);
    System.out.println(current.egressStatus); // "active", "held" or "unavailable"
    ```
  </TabItem>
</Tabs>

| Status | What it means |
|---|---|
| `active` | The filter is working as listed. |
| `unavailable` | The filter service is down or restarting. Traffic comes back by itself within seconds of it returning. |
| `held` | The policy could not be applied. The sandbox gets no outbound traffic until it can be. |

A create that lists names while the server's filter cannot take it returns `503`, with code `egress_gateway_unavailable` and a `Retry-After` header. Retry it. In a cluster, these creates only go to servers whose filter is ready.

## Change the policy of a running sandbox

`setNetworkPolicy` replaces the sandbox's whole outbound policy while it runs. Any list you leave out is cleared, so an empty call gives full internet access. The call returns once the new policy is in force. Connections the new policy does not allow are closed.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    await sandbox.setNetworkPolicy({
      networkAllowOut: ['pypi.org', '*.pythonhosted.org', 'registry.npmjs.org'],
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox.set_network_policy({
        'networkAllowOut': ['pypi.org', '*.pythonhosted.org', 'registry.npmjs.org'],
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    _, err := sandbox.SetNetworkPolicy(ctx, sdktypes.NetworkPolicyOptions{
        NetworkAllowOut: []string{"pypi.org", "*.pythonhosted.org", "registry.npmjs.org"},
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    // set_network_policy updates the sandbox value, so declare it with `let mut sandbox`.
    sandbox.set_network_policy(NetworkPolicyOptions {
        network_allow_out: vec![
            "pypi.org".to_string(),
            "*.pythonhosted.org".to_string(),
            "registry.npmjs.org".to_string(),
        ],
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    sandbox.setNetworkPolicy(
        new NetworkPolicyOptions()
            .setNetworkAllowOut(List.of("pypi.org", "*.pythonhosted.org", "registry.npmjs.org"))
    );
    ```
  </TabItem>
</Tabs>

- **Safe to retry.** Sending the policy a sandbox already has changes nothing.
- **Never open, even for a moment.** Outbound traffic is shut during the swap, so neither the old policy nor the new one is ever skipped.
- **Stopped sandboxes** keep the new policy and apply it when they start.
- **A sandbox that is still being created** answers `409`. Retry once it is up.
- **Failures** return `503` with a code that says what happened:

| Code | What it means |
|---|---|
| `spec_commit_failed` | Nothing changed. In a cluster, the new policy could not be saved. |
| `apply_failed_held` | The policy is saved but could not be applied. The sandbox has no outbound traffic until a retry succeeds. |

## Which sandbox types support it

| Runtime (kind of sandbox) | How names are checked |
|---|---|
| Docker, containerd, gVisor | By the server's filter service, which checks name lookups and the site name in each HTTPS or HTTP request. |
| WASM | Inside the WASM network layer. A refused connection returns an error that names the host and the rule. |
| V8 isolate | By the isolate's outbound proxy, which always uses HTTPS and returns a `403` that names the host. |
| Firecracker | By the server's filter service, reached through each VM's own network device. `networkBlockAll` and address lists are enforced on that device. |

Some servers cannot check names. A create that lists names on one of them gets `501`. Lists of address ranges still work there. See [For server operators](#for-server-operators) for why.

### From the E2B SDK

The [E2B SDK](/using-e2b-sdk/) compatibility layer maps `network.allowOut` and `network.denyOut` onto the same rules. That works on create and through `updateNetwork` on a running sandbox.

One case reads more strictly here than on E2B. `allowOut` with no `denyOut` is an allow list here, but E2B would allow everything. `allowOut` together with `denyOut: [ALL_TRAFFIC]` means the same on both, so use that form.

## Limits

- **IPv4 only.** As with [Block or allow the internet](/network-isolation/), IPv6 traffic is not filtered.
- **Names, not paths.** The filter decides by site name. It does not read inside HTTPS, so on its own it cannot allow one path or method and refuse another. [Rules and inspection](/egress-rules-and-inspection/) adds that, for plain HTTP and for HTTPS sites you choose to inspect.
- **Firecracker** supports everything on this page: names, address lists and `networkBlockAll`, at create and with `setNetworkPolicy`. Each VM has its own network device, so another VM cannot pretend to be it. [Rules and inspection](/egress-rules-and-inspection/) is not supported there (`501`).

## For server operators

| Setting | What it does | Default |
|---|---|---|
| `SB_EGRESS_FQDN_ENABLED` | Runs the filter service (the egress gateway) that checks website names. It does nothing until a sandbox uses a name. When off, creates that list names get `501`. | `true` |
| `SB_EGRESS_OPERATOR_FILE` | Path to the private-network policy file below. | Not set |

A server cannot check names, and answers `501`, in these cases:

- Privileged sandboxes are turned on for it.
- Its sandbox network bridge carries IPv6.
- Its host firewall drops the traffic the filter service redirects. The filter service tests for this itself when it starts.

### Private networks

A deployment may have no route to the internet, such as a bank's private cloud. The operator can describe that network in one file, `/etc/sandboxd/egress-policy.yaml`, set through `SB_EGRESS_OPERATOR_FILE`. Every setting in it is optional. Without the file, nothing changes.

```yaml
version: 1
internal_zone:
  suffixes: [corp.bank.internal]     # names that may resolve to internal ranges
  cidrs: [10.0.0.0/8]                # the internal ranges those names may reach
default_policy:
  mode: allowlist                    # open | block_all | allowlist, for creates that set no egress
  allow_out: [artifactory.corp.bank.internal, "org:mirrors"]
org_profiles:                        # org:<name> lists every account can use
  mirrors:
    allow_out: [pypi.mirror.corp.bank.internal, npm.mirror.corp.bank.internal]
    description: package mirrors
builtin_profiles: false              # refuse builtin: profiles, which name public hosts
ceiling:
  allow_out: ["*.corp.bank.internal", pypi.org]   # every allow entry must fit inside
deny_cidrs: [10.50.0.0/16]           # always dropped, for every sandbox
node_control_port_guard: true        # sandboxes can't reach AerolVM control ports on any node
upstream_proxy:
  url: http://proxy.corp.bank.internal:3128
  auth_file: /etc/sandboxd/proxy-auth   # user:password, mode 0600
  no_proxy: [mirror.corp.bank.internal]
```

| Setting | What it does |
|---|---|
| `internal_zone` | A name under a listed suffix may resolve to an address in the listed ranges, and only that name's address is opened. Raw connections into the range stay blocked. So do other names that resolve there, and metadata addresses. |
| `default_policy` | The policy a create gets when it says nothing about outbound traffic. It is saved with the sandbox, so later edits to the file never change a running sandbox. Org profiles it names are the exception: they stay references and follow edits. |
| `org_profiles` | Lists every account can use as `org:<name>`. An edit reaches the sandboxes using one within about 10 seconds. See [Org profiles](/egress-profiles-and-learn-mode/#org-profiles). |
| `builtin_profiles` | `false` refuses [built-in profiles](/egress-profiles-and-learn-mode/#built-in-profiles) with `400`, for networks where their public sites cannot be reached anyway. |
| `ceiling` | The outer limit for every allow entry. An entry that does not fit inside is refused with `400`, naming it. |
| `deny_cidrs` and `node_control_port_guard` | Applied to every sandbox on the server, whatever its own policy says. |
| `upstream_proxy` | Allowed names outside the internal zone and `no_proxy` go out through this proxy. Their name lookups return placeholder addresses, since the proxy, not the sandbox, looks up outside names. `host:port` entries for these names must use port 80 or 443. |

If the file is there but invalid when sandboxd starts, every create is refused with `503` and code `egress_operator_config_invalid` until you fix it.

### Certificates without the internet

Sandbox URLs and [custom domains](/custom-domains/) get their HTTPS certificates from Let's Encrypt by default. A private network cannot reach it. Point them at your own certificate authority (CA, the service that issues certificates) instead. These settings use ACME, the protocol Let's Encrypt uses to issue certificates.

| Setting | install.sh flag | What it does |
|---|---|---|
| `SB_TLS_ACME_CA` | `--acme-ca <url>` | The ACME directory to issue from, such as your PKI or step-ca. `https` only. |
| `SB_TLS_ACME_CA_ROOT` | `--acme-ca-root <pem>` | The root certificate to trust when talking to that CA. An absolute path. |
| `SB_TLS_ISSUER` | `--tls-issuer internal` | Caddy's own CA issues every certificate, with no DNS provider. For labs: clients must trust Caddy's root certificate. |

- The install flags set both the wildcard certificates and the custom-domain certificates. The environment variables alone cover custom domains only.
- Changes take effect the next time sandboxd starts. Unset them to go back to Let's Encrypt.
- With an ACME CA, a custom domain's DNS must still point the CA at the server that receives public traffic, for its HTTP check. Caddy's own CA needs no check.
