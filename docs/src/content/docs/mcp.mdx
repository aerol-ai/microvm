`aerolvm mcp` lets an AI coding tool use AerolVM sandboxes. It speaks MCP, the [Model Context Protocol](https://modelcontextprotocol.io): a standard way for AI tools to call outside tools. The agent gets tools to create sandboxes, run commands, read and edit files, run background programs and share ports. It then works in a sandbox instead of on your machine.

It is part of the [aerolvm CLI](/cli/), so it is the same program. Your AI tool starts it on your machine. Your server can also offer the same tools over the web; see [Connect without installing anything](#connect-without-installing-anything).

## Set up your AI tool

First [install the aerolvm CLI](/cli/#install). You also need your server's address and an API token, the same ones the [SDKs](/sdk-setup/) use. Then follow the steps for your tool.

## Tools the agent gets

Tools come in three sets. The server offers `core` unless you pass `--toolsets` with a comma list, or `all`.

| Tool set | Tools |
|---|---|
| `core` | `sandbox_create`, `sandbox_list`, `sandbox_destroy`, `exec`, `read_file`, `write_file`, `list_files`, `expose_port` |
| `files` | `edit_file` (replaces one exact match), `search_files` (by name), `grep_files` (by content) |
| `process` | `start_process`, `process_logs`, `stop_process`, for dev servers and other programs that keep running |

`--read-only` offers only the tools that change nothing: listing, reading, searching and logs.

Every tool that works on a sandbox takes a `sandbox` argument: its ID or name. `sandbox_create` is safe to repeat. Asking for a name you already have returns that sandbox instead of making a second one. Its `allow_hosts` argument limits where the new sandbox can connect: host names, `*.` wildcards, `host:port` pairs and IP ranges. See [Allow only some websites](/egress-domain-filtering/).

## Give the agent just one sandbox

Pinned mode gives the agent one sandbox and nothing else:

```bash
aerolvm mcp --sandbox my-agent --create-if-missing --image python:3.12
```

- The `sandbox` argument disappears from every tool. `sandbox_create`, `sandbox_list` and `sandbox_destroy` are not offered.
- With `--create-if-missing`, the sandbox is created on the first tool call that needs it, not when the server starts.
- If the sandbox goes away, for example after it was deleted for sitting idle, the next call creates a new one. The result tells the agent that files from earlier calls are gone.
- `--ephemeral` deletes the sandbox when the MCP server exits.
- `--allow-host` limits where the created sandbox can connect. Repeat it or pass a comma list. It needs `--create-if-missing`. A server that is not pinned refuses it, because there the agent picks its own `allow_hosts`.

```bash
aerolvm mcp --sandbox my-agent --create-if-missing --image python:3.12 --allow-host pypi.org,*.pythonhosted.org
```

Pass the same flags to `aerolvm mcp config` to get a setup snippet that starts the server pinned.

## Settings that keep costs down

Agents forget to clean up, so sandboxes created through MCP clean up after themselves:

- They **stop after 30 minutes idle**. A stopped sandbox keeps its files, and the next tool call starts it again.
- They are **deleted after 24 hours idle**.

Change these with `--stop-if-idle` and `--destroy-if-idle`, or turn them off with `--keep`. A server that is not pinned also allows at most 5 creates per session (`--max-creates`, `0` for no limit). So an agent stuck in a loop cannot fill your server.

Every sandbox the MCP server creates gets the tag `aerolvm.created_by=mcp`, unless the agent sets that tag itself. `aerolvm list --tag aerolvm.created_by=mcp` finds them.

## Results sized for the agent

Tool results are kept small enough for an AI model to read:

- **`exec`** keeps 16 KB of each output stream: the first quarter and the last three quarters. It says how much it cut. Change the size with `--max-output-bytes`. A command that runs past its time limit is stopped and reports exit code 124.
- **`read_file`** returns up to 2,000 lines or 256 KB per call, and says where to continue. It refuses binary files.
- **`sandbox_list`** returns 20 sandboxes per page, with a token for the next page.
- **`search_files` and `grep_files`** cap their matches and say when they cut some.

Errors come back as tool results with a code the agent can act on, such as `not_found`, `edit_conflict`, `binary_file` or `create_limit`. They are not protocol failures.

### Differences between sandbox types

- **WebAssembly sandboxes** have no streamed commands. `exec` waits for the command to finish there, and refuses output over 4 MB with `output_too_large`.
- **V8 isolate sandboxes** have no shell or files. The tools refuse them with `unsupported_runtime`, and `sandbox_create` does not offer `isolate`. Call an isolate's handler from an SDK instead; see [V8 isolate](/isolate-sandbox/).

## Connect without installing anything

Your server can offer the same tools over the web at `/mcp`, using MCP's Streamable HTTP transport. An AI tool then connects with only an address and a token. This is off by default; see [For server operators](#for-server-operators).

The web endpoint is always pinned to one sandbox. The address's query string picks the sandbox and the options:

| Parameter | What it does |
|---|---|
| `sandbox` | The sandbox name or ID. Required. |
| `create_if_missing` | `true` to create the sandbox on first use. |
| `image`, `runtime` | What to create the sandbox from. |
| `allow_host` | Where the created sandbox may connect, as a comma list. Needs `create_if_missing`. |
| `toolsets` | `core` (the default), `files`, `process` or `all`, as a comma list. |
| `read_only` | `true` to offer only the tools that change nothing. |

Send your API token as a bearer token. For example, in Claude Code:

```bash
claude mcp add --transport http aerolvm "https://sandbox.example.com/mcp?sandbox=my-agent&create_if_missing=true" --header "Authorization: Bearer $SB_PAT_TOKEN"
```

- **Any server in a cluster can answer.** The endpoint keeps no state between requests.
- **Each call runs with your token's permissions,** through the same checks as a direct API call.
- **The first call that creates the sandbox says so** in its result.
- **`exec` always waits for the command to finish** on this endpoint, on every sandbox type, with the 4 MB limit above.

## For server operators

| Variable | What it does | Default |
|---|---|---|
| `SB_MCP_ENABLED` | Serve the MCP tools at `/mcp`. | `false` |
| `SB_MCP_ALLOWED_ORIGINS` | Web page origins allowed to call `/mcp`, as a comma list. A request with any other `Origin` header is refused. This blocks DNS rebinding, a trick that lets a web page reach servers on your network. Desktop and CLI tools send no `Origin` and are not affected. | empty |
| `SB_MCP_ALLOWED_HOSTS` | The `Host` values `/mcp` answers to, as a comma list. | empty (any host) |
| `SB_MCP_RATE_LIMIT` | Requests per second for each token, with short bursts up to twice that. `0` turns the limit off. | `20` |

The server counts tool calls by tool and result in the `aerolvm_mcp_tool_calls_total` metric. It writes one log line per call, with the tool, sandbox, owner, result and time taken. It never logs arguments or output.

## Same thing from the SDK

What a pinned server does on its first `exec`: get or create `my-agent` with the MCP idle settings, then run a command.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox =
      (await client.getByName("my-agent")) ??
      (await client.create({
        name: "my-agent",
        image: "python:3.12",
        lifecycle: {
          stopIfIdleFor: 30 * 60 * 1_000_000_000,         // 30 minutes, in nanoseconds
          destroyIfIdleFor: 24 * 60 * 60 * 1_000_000_000, // 24 hours, in nanoseconds
        },
      }));

    const result = await sandbox.exec("python -V");
    console.log(result.exitCode, result.stdout);
    ```
  </TabItem>
