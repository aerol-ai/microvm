The AerolVM MCP server lets an AI coding tool work inside sandboxes instead of on your computer. The agent can create a sandbox, run commands, read and edit files, and share a web server from it.

MCP, the [Model Context Protocol](https://modelcontextprotocol.io), is a standard way for AI tools to call outside tools. The MCP server is part of the [aerolvm CLI](/cli/): it is the same program, run as `aerolvm mcp`.

## Before you start

- **Install the aerolvm CLI.** See [Install](/cli/#install).
- **Have your server's address and token ready.** They are the same ones the SDKs use. After the [Quickstart](/quick-start/), the address is `http://localhost:21212` and the token is the one you picked.

## Set up your AI tool

<Tabs syncKey="mcp-client">
  <TabItem label="Claude Code">
    Install the AerolVM plugin. It adds the MCP server, plus a short skill that teaches Claude the CLI:

    /plugin marketplace add aerol-ai/microvm

    To add only the MCP server, without the plugin, run this in a terminal where `SB_PAT_TOKEN` is set:

    claude mcp add aerolvm -e SB_API_URL=http://localhost:21212 -e SB_PAT_TOKEN="$SB_PAT_TOKEN" -- aerolvm mcp
    ```
  </TabItem>

          }
        }
      }
    }
    ```
  </TabItem>

## Check that it works

Restart your AI tool, then ask it:

```text
Create an AerolVM sandbox from python:3.12 and run python -V in it.
```

The agent creates a sandbox, runs the command, and tells you the Python version. In Claude Code, `/mcp` also shows whether `aerolvm` is connected.

## What the agent can do

The tools come in three sets. Only `core` is on by default.

| Set | What the agent can do | Tools |
|---|---|---|
| `core` | Create, list and delete sandboxes. Run commands. Read, write and list files. Share a port. | `sandbox_create`, `sandbox_list`, `sandbox_destroy`, `exec`, `read_file`, `write_file`, `list_files`, `expose_port` |
| `files` | Change part of a file. Find files by name. Search inside files. | `edit_file`, `search_files`, `grep_files` |
| `process` | Start a program that keeps running, such as a dev server. Read its output. Stop it. | `start_process`, `process_logs`, `stop_process` |

Add `--toolsets` to the `aerolvm mcp` command to choose sets, such as `--toolsets core,files` or `--toolsets all`. Add `--read-only` to offer only tools that change nothing.

The agent can also limit where a new sandbox may connect, with the `allow_hosts` argument of `sandbox_create`. See [Allow only some websites](/egress-domain-filtering/).

## Keep the agent in one sandbox

Pinned mode gives the agent one sandbox and nothing else. It cannot create, list or delete sandboxes:

```bash
aerolvm mcp --sandbox my-agent --create-if-missing --image python:3.12
```

`--create-if-missing` creates `my-agent` the first time the agent needs it. Add `--allow-host pypi.org,*.pythonhosted.org` to limit where that sandbox can connect. Pass the same flags to `aerolvm mcp config` to get a setup that starts the server pinned.

## Built-in limits

Agents forget to clean up, so sandboxes made through MCP clean up after themselves:

- They **stop after 30 minutes idle**. They keep their files, and the next tool call starts them again.
- They are **deleted after 24 hours idle**.
- An agent can create **at most 5 sandboxes per session**, so an agent stuck in a loop cannot fill your server. Pinned mode has no such limit, because it uses one sandbox.

Change these with `--stop-if-idle`, `--destroy-if-idle` and `--max-creates` (`0` means no limit). `--keep` turns the idle timers off.

## Reference

### Use your saved login

If you ran [`aerolvm login`](/cli/#sign-in) on this machine, the MCP server reads that login. Then no token goes in your tool's config. In Claude Code that is:

```bash
claude mcp add aerolvm -- aerolvm mcp
```

`aerolvm login` needs the newest CLI build. See [Install](/cli/#install).

### More about pinned mode

- The `sandbox` argument disappears from every tool.
- If the sandbox goes away, for example after it was deleted for sitting idle, the next call creates a new one. The result tells the agent that files from earlier calls are gone.
- `--ephemeral` deletes the sandbox when the MCP server exits.
- `--allow-host` needs `--create-if-missing`. A server that is not pinned refuses it, because there the agent picks its own `allow_hosts`.

### Other things to know

- **Sandboxes are named by ID or name.** Every tool that works on a sandbox takes a `sandbox` argument with either one.
- **`sandbox_create` is safe to repeat.** Asking for a name you already have returns that sandbox instead of making a second one.
- **Sandboxes are tagged.** Each one the MCP server creates gets the tag `aerolvm.created_by=mcp`. `aerolvm list --tag aerolvm.created_by=mcp` finds them.

### Results sized for the agent

Tool results stay small enough for an AI model to read:

- **`exec`** keeps 16 KB of each output stream: the first quarter and the last three quarters. It says how much it cut. Change the size with `--max-output-bytes`. A command that runs past its time limit is stopped and reports exit code 124.
- **`read_file`** returns up to 2,000 lines or 256 KB per call, and says where to continue. It refuses binary files.
- **`sandbox_list`** returns 20 sandboxes per page, with a token for the next page.
- **`search_files` and `grep_files`** cap their matches and say when they cut some.

Errors come back as tool results with a code the agent can act on, such as `not_found`, `edit_conflict`, `binary_file` or `create_limit`.

### Sandbox types

- **WebAssembly sandboxes** have no streamed commands. `exec` waits for the command to finish there, and refuses output over 4 MB with `output_too_large`.
- **V8 isolate sandboxes** have no shell or files. The tools refuse them with `unsupported_runtime`, and `sandbox_create` does not offer `isolate`. Call an isolate's handler from an SDK instead. See [V8 isolate](/isolate-sandbox/).

### Connect over the web

Your server can also offer the same tools at `/mcp`, so an AI tool connects with only an address and a token. Nothing is installed on your machine. This is off until the server operator turns it on (see [For server operators](#for-server-operators)).

The web endpoint is always pinned to one sandbox. The address's query string picks the sandbox and the options:

| Parameter | What it does |
|---|---|
| `sandbox` | The sandbox name or ID. Required. |
| `create_if_missing` | `true` to create the sandbox on first use. |
| `image`, `runtime` | What to create the sandbox from. |
| `allow_host` | Where the created sandbox may connect, as a comma list. Needs `create_if_missing`. |
| `toolsets` | `core` (the default), `files`, `process` or `all`, as a comma list. |
| `read_only` | `true` to offer only the tools that change nothing. |

Send your API token as a bearer token. For example, in Claude Code:

```bash
claude mcp add --transport http aerolvm "https://sandbox.example.com/mcp?sandbox=my-agent&create_if_missing=true" --header "Authorization: Bearer $SB_PAT_TOKEN"
```

- **Any server in a cluster can answer.** The endpoint keeps nothing between requests.
- **Each call runs with your token's permissions,** through the same checks as a direct API call.
- **The first call that creates the sandbox says so** in its result.
- **`exec` always waits for the command to finish** here, on every sandbox type, with the 4 MB limit above.

### For server operators

| Variable | What it does | Default |
|---|---|---|
| `SB_MCP_ENABLED` | Serve the MCP tools at `/mcp`. | `false` |
| `SB_MCP_ALLOWED_ORIGINS` | Web page origins allowed to call `/mcp`, as a comma list. A request with any other `Origin` header is refused. This blocks DNS rebinding, a trick that lets a web page reach servers on your network. Desktop and CLI tools send no `Origin` and are not affected. | Empty |
| `SB_MCP_ALLOWED_HOSTS` | The `Host` values `/mcp` answers to, as a comma list. | Empty (any host) |
| `SB_MCP_RATE_LIMIT` | Requests per second for each token, with short bursts up to twice that. `0` turns the limit off. | `20` |

The server counts tool calls by tool and result in the `aerolvm_mcp_tool_calls_total` metric. It writes one log line per call, with the tool, sandbox, owner, result and time taken. It never logs arguments or output.
