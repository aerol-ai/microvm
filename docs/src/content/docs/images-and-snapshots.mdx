Every container and Firecracker sandbox starts from an image. An image is a packaged Linux system with its programs already installed, such as `ubuntu:22.04` or `python:3.12-slim`. A snapshot is an image you made yourself, from a sandbox you already set up.

New to sandboxes? Start with [Create and manage](/sandboxes/) first.

## Choose an image

`image` is the one option every container and Firecracker sandbox needs. Any image name works, such as `ubuntu:22.04`, `python:3.12-slim` or `ghcr.io/your-org/app:1.4`. The server downloads (pulls) the image the first time you use it. Later creates reuse the copy it already has, so they start much faster.

WebAssembly and V8 isolate sandboxes use a module instead of an image. See [WebAssembly (WASM)](/wasm-sandbox/) and [V8 isolate](/isolate-sandbox/).

### Use an image from a private registry

A registry is a server that stores images, like Docker Hub or GitHub's `ghcr.io`. If yours needs a login, pass it in `registry`. The server uses it to pull the image.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: "ghcr.io/your-org/app:1.4",
      registry: {
        server: "ghcr.io",
        username: "your-user",
        password: process.env.GHCR_TOKEN!,
      },
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    import os

    sandbox = client.create(
        image="ghcr.io/your-org/app:1.4",
        registry={
            "server": "ghcr.io",
            "username": "your-user",
            "password": os.environ["GHCR_TOKEN"],
        },
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image: "ghcr.io/your-org/app:1.4",
        Registry: &sdktypes.RegistryAuth{
            Server:   "ghcr.io",
            Username: "your-user",
            Password: os.Getenv("GHCR_TOKEN"),
        },
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    use aerolvm_sdk::RegistryAuth;

    let sandbox = client.create(CreateOptions {
        image: "ghcr.io/your-org/app:1.4".into(),
        registry: Some(RegistryAuth {
            server: "ghcr.io".into(),
            username: "your-user".into(),
            password: std::env::var("GHCR_TOKEN").unwrap(),
        }),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(new CreateOptions()
        .setImage("ghcr.io/your-org/app:1.4")
        .setRegistry(new RegistryAuth()
            .setServer("ghcr.io")
            .setUsername("your-user")
            .setPassword(System.getenv("GHCR_TOKEN"))));
    ```
  </TabItem>
</Tabs>

### Choose what runs when the sandbox starts

When a container sandbox starts, it runs the image's own start command in the background. That is the `ENTRYPOINT` and `CMD` from the image's Dockerfile. To run something else, pass `containerCommand`.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: "python:3.12-slim",
      containerCommand: ["python3", "-m", "http.server", "8080"],
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create(
        image="python:3.12-slim",
        container_command=["python3", "-m", "http.server", "8080"],
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:            "python:3.12-slim",
        ContainerCommand: []string{"python3", "-m", "http.server", "8080"},
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "python:3.12-slim".into(),
        container_command: Some(vec![
            "python3".into(), "-m".into(), "http.server".into(), "8080".into(),
        ]),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(new CreateOptions()
        .setImage("python:3.12-slim")
        .setContainerCommand(List.of("python3", "-m", "http.server", "8080")));
    ```
  </TabItem>
</Tabs>

You do not need a start command to use a sandbox. You can run everything with [Run commands](/exec-streaming/) or [Terminal sessions](/sessions/). The sandbox stays up even if the start command exits.

## Start from a snapshot

A snapshot is a saved copy of a sandbox's files. Install your tools once, save the sandbox as a snapshot, and start new sandboxes from it with everything already in place. To make one, see [Snapshots](/snapshots/).

To use a snapshot, pass its name where you would normally pass an image:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({ image: "py-ready" });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create(image="py-ready")
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{Image: "py-ready"})
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "py-ready".into(),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(new CreateOptions().setImage("py-ready"));
    ```
  </TabItem>
</Tabs>

- **A snapshot name wins over a registry image** with the same name. Snapshot names are short words, so this rarely matters.
- **CPU, memory and disk are not copied.** The new sandbox gets the normal defaults unless you set them. See [CPU, memory and disk](/sandboxes/#give-the-sandbox-more-cpu-memory-or-disk).
