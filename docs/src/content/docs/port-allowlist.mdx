A port is a number that tells the sandbox which program gets the traffic. Every port in a sandbox starts **closed** to the public internet. A port opens only when you call `exposePort` for it.

The server keeps a list of the ports you exposed for each sandbox. This list is the **port allowlist**. Traffic to any port that is not on the list is refused. This stops a database, a debug tool or a forgotten test server from being open to anyone by accident.

<Aside type="note">
Public URLs need a server install that runs the web proxy. On a local install, `exposePort` adds the port to the list but nothing answers at the URL. See [Share a web app](/preview/).
</Aside>

## Open a port

This creates a public sandbox, exposes port 3000, and prints both URLs that now reach it.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

    ```ts
      allowPublicTraffic: true,

    const exposure = await sandbox.exposePort(3000);
    console.log(exposure.url);                        // port URL
    console.log(`${sandbox.publicURL}/proxy/3000/`);  // proxy path
    ```

On a server with a domain, the output looks like this:

```text
https://sb-9f2c41d07a3e5b86-3000.sandbox.example.com
https://sb-9f2c41d07a3e5b86.sandbox.example.com/proxy/3000/
```

This example creates the sandbox with `allowPublicTraffic: true` so that `publicURL` is set from the start. Without it, the first `exposePort` call makes the sandbox public. The copy of the sandbox in your code still has an empty `publicURL` until you call `refresh()`.

## The two URLs for an open port

| URL | Looks like | When to use it |
|---|---|---|
| Port URL | `https://<sandbox-id>-<port>.<domain>` | The usual choice for web apps and APIs. `exposePort` returns it. |
| Proxy path | `https://<sandbox-id>.<domain>/proxy/<port>/` | When you want every port under the sandbox's main URL. |

On a server without a domain, there is only the path form: `http://<server-ip>/<sandbox-id>/proxy/<port>/`. That is the URL `exposePort` returns there, so you do not need to build it yourself.

Before you expose a port, both URLs refuse the request with an error such as `403` or `404`.

## Close a port

`unexposePort` takes the port off the allowlist and removes its public URL. Both URLs refuse requests again right away. Calling it for a port that is not open does nothing.

## What happens when a sandbox restarts

The server saves the allowlist. When you stop a sandbox and start it again, the same ports open again with the same URLs. You do not need to call `exposePort` again.

## If a URL returns 403 or 404

1. **Check that the port is on the list.** Refresh the sandbox and look at its exposed ports (code below).
2. **Check that `exposePort` succeeded.** It throws an error if it could not open the port.
3. **Check that the sandbox is running.** Its status must be `started`. A stopped sandbox does not answer, unless it is a [serverless sandbox](/serverless/) that wakes on traffic.

If the URL returns `502 Bad Gateway` instead, the port is open but nothing in the sandbox is listening on it. Check that your server is running and listens on `0.0.0.0`.

## For server operators

The allowlist lives on the server, in the sandbox database. Each `exposePort` and `unexposePort` call updates the list and adds or removes the matching route in Caddy (the web proxy in front of the server). The server also pushes the list to the sandbox's built-in helper program, which serves the proxy path and refuses ports that are not on it. When a sandbox starts again, the server puts its routes and its list back.
