A **runbook** is a step-by-step guide for one kind of problem. AerolVM's runbooks live in the repository under [`setup/runbooks/`](https://github.com/aerol-ai/microvm/tree/main/setup/runbooks). Each Prometheus alert that ships with AerolVM links straight to the runbook for it.

Most runbooks follow the same pattern: how serious the problem is, safety rules, checks to run first, the fix, and how to confirm it worked. Many end with a drill checklist so you can practice.

## Pick a runbook

| Runbook | Use it when |
|---|---|
| [Backup and restore](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/backup-restore.md) | You need to restore a node, recover lost local data, or prove your backups work. |
| [Cluster upgrades](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/cluster-upgrades.md) | An upgrade rollout failed, is stuck, or waits on a node marked `manual` or `skipped`, or you need to finalize or roll back. |
| [Lost-quorum recovery](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/lost-quorum-recovery.md) | The cluster has no leader because too many voting servers are gone, and you cannot bring a majority back. This is a last resort. |
| [SLO breach](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/slo-breach.md) | Any service-level alert fires and the cause is not clear. Start here, then move to a narrower runbook. |
| [Image-pull storm](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/image-pull-storm.md) | Image downloads are queued, failing, rate-limited, or held back after repeated failures. |
| [Cluster ingress topology](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/cluster-ingress-topology.md) | The `SandboxdClusterTopologyViolation` alert fires: more than 10 ingress nodes without a shard-aware router, or mixed roles in a cluster of more than 10 nodes. |
| [Egress gateway](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/egress-gateway.md) | A `SandboxdEgress*` alert fires, or creates that use a website allow list return `503 egress_gateway_unavailable`. |
| [Secrets and audit](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/secrets-and-audit.md) | Secret audit or copy alerts fire, a stored credential will not open, or `failover_ready` stays `false`. |
| [Firecracker template health](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/firecracker-template-health.md) | Alerts fire for Firecracker template builds, uploads, downloads or rebuilds. |
| [Container engine coexistence](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/containerd-engine-coexistence.md) | You switch a node between Docker and containerd, or run both on one node while you drain it. |
| [WASM runtime health](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/wasm-runtime-health.md) | WASM sandboxes are stuck in `passivated` or `awaiting_runtime`, or stay cold after failover. |
| [Isolate jail](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/isolate-jail.md) | You need to check or debug the lock-down around `workerd` for V8 isolates. |
| [Isolate workerd upgrade](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/isolate-workerd-upgrade.md) | You upgrade, or roll back, the fixed `workerd` version that V8 isolates use. |
| [Remote MCP](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/remote-mcp.md) | Agents that use the server's remote MCP endpoint (`/mcp`) report failures, or `SandboxdRemoteMCPErrorRate` fires. |
| [Identity and access](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/identity-and-access.md) | An identity alert fires (the server token used from outside, a stale token list, failing key fetches, identity files that differ), your identity provider is down, or you rotate the server token or the metrics scrape token, make the first admin token, or limit the server token to the server. |

An SLO (service level objective) is a target your service should meet, such as how fast creates finish. Quorum means a majority of the voting servers. See the [Glossary](/cluster-glossary/) for other cluster words.

## The first five minutes of any incident

The [runbook overview](https://github.com/aerol-ai/microvm/blob/main/setup/runbooks/README.md) sets out the same start for every incident:

1. Find the alert that fired and the cluster it affects.
2. Open the Grafana dashboard and the current Prometheus alerts page.
3. Save the cluster leader, the member list and the metrics from one server, one worker and one ingress node (a node that takes public traffic). `aerolvm cluster-info` and `aerolvm get nodes -o wide` print the leader and members; so does the [Dashboard](/dashboard/).
4. Stop deploys and changes to the cluster's nodes until the incident lead says it is safe.
5. Pick the narrowest runbook above. Follow its checks before you change anything.

It also names four incident roles. The **incident lead** makes decisions and keeps the timeline. The **operator** runs the commands. **Comms** keeps users updated. The **observer** records metrics before, during and after the fix. On a small team one person can hold several roles, but keep one lead and one log of commands.

## Tools the runbooks use

You need no copy of the repository. Every tool below ships in a release or inside a program you already have.

| Tool | Where it runs | What it does |
|---|---|---|
| `aerolvm` | Your computer | The cluster commands: `get nodes`, `cordon`, `drain`, `delete node`, `join-command`, `upgrade`, `release pull`. See [the aerolvm CLI](/cli/#run-a-cluster). |
| `sudo sandboxd init`, `join`, `preflight`, `adopt`, `reset` | On a node | Start a cluster, add a machine, check a machine first, bring an older cluster onto one-line joins, take a machine out. See [Cluster setup](/cluster/). |
| `sudo sandboxd backup`, `restore`, `recover-quorum` | On a node | Save a node's database, Raft data and settings into one archive, put it back, and the last-resort lost-quorum recovery. |
| `sudo sandboxd upgrade node` | On a node | Upgrades this one node. Only for a node that takes no remote upgrade, or the first hop from an old release. |
| [`install.sh`](https://github.com/aerol-ai/microvm/releases/latest/download/install.sh) | On a node | Installs AerolVM on one machine. With `init` or `join` at the end, it also starts or joins a cluster. |
| [`uninstall.sh`](https://github.com/aerol-ai/microvm/releases/latest/download/uninstall.sh) | On a node | Removes the AerolVM server from a machine. |
| `aerolvm-ops-<release>.tar.gz` | Your monitoring | Every release ships one: the Prometheus alert rules, the Grafana dashboards, the Alertmanager example and these runbooks, for that release. |

Use the copies that match the release your servers run. `sudo sandboxd version` prints it, such as `v0.7.0`. For another release's files, use `https://github.com/aerol-ai/microvm/releases/download/<release>/<file>`.

<Aside type="caution">
Use `sandboxd recover-quorum` only while you follow the lost-quorum runbook. It can make the cluster keep changes that a majority never agreed on. Try to bring the original voting servers back first.
</Aside>

**The old scripts are going away.** `cluster-init.sh` and `cluster-join.sh` still ship in this release, as thin wrappers over `sandboxd init` and `sandboxd join`, with `cluster-sign-node.sh` for the old two-step join. All three leave in a later release. `sandboxd-backup.sh`, `sandboxd-restore.sh` and `raft-lost-quorum-recover.sh` in the source now call `sandboxd backup`, `restore` and `recover-quorum`.

## Ansible playbooks

Ansible is a tool that runs the same steps on many servers over SSH. You do not need it to upgrade: `aerolvm upgrade apply` upgrades every node from your computer. The playbooks live in [`Ansible/playbooks/`](https://github.com/aerol-ai/microvm/tree/main/Ansible/playbooks), for host settings only. Run them from the `Ansible` folder, which holds the server list and settings. The [Ansible README](https://github.com/aerol-ai/microvm/blob/main/Ansible/README.md) has the full guide.

| Playbook | What it does |
|---|---|
| `ping.yml` | Checks that Ansible can reach every node with SSH and `sudo`. Run it before anything risky. |
| `configure-ops.yml` | Pushes operations settings to every node, plus the Grafana dashboard, alert rules, Alertmanager example and the main runbooks. |
| `prepare-role-change.yml` | Drains a node and waits until it owns no sandboxes, before you change its role or replace it. `aerolvm drain` does the same from your computer. |
| `tail-logs.yml` | Shows the latest server log lines from every node. |
| `stage-wasm-modules.yml` | Copies the standard WASM modules onto every node ahead of time, and checks each file's checksum. |

## Put the runbooks on your servers

`configure-ops.yml` copies the main runbooks to each node, next to the Grafana dashboard, the Prometheus alert rules and the Alertmanager example. From the top of the repository:

```bash
cd Ansible
ansible-playbook playbooks/configure-ops.yml
```

The runbooks land in `/etc/sandboxd/runbooks` by default.

## Practice with drills

Run these drills on a test (staging) cluster at least once a month. They prove your commands, access, metrics and escalation path work before a real outage.

- **Backup restore:** restore the latest archive onto a replacement node.
- **Lost quorum:** talk through the decision steps, without creating `peers.json`.
- **Image-pull storm:** point a test workload at an image tag that does not exist, and check that the backoff alerts fire.
- **Firecracker template health:** mark a test template `unhealthy` with the rebuild endpoint, and check that the rebuild clears the alert.
- **SLO breach:** create a backlog of creates with a small, controlled load test. Check the alert, the dashboard and the fix steps.

Record each result in the drill template inside the runbook.
