A tag is a label you attach to a sandbox, made of a key and a value, like `tenant: acme`. Tags let you split one AerolVM server into views: one per customer, per environment or per user.

Tags are only labels, and they do not need to be unique. They do not change where a sandbox runs, what it costs or what it can reach.

## Add tags when you create a sandbox

Pass a map of keys and values in `tags`. You set tags at create time. The SDKs have no call to change them later.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: "ubuntu:22.04",
      tags: { tenant: "acme", environment: "staging" },
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create(
        image="ubuntu:22.04",
        tags={"tenant": "acme", "environment": "staging"},
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image: "ubuntu:22.04",
        Tags: map[string]string{
            "tenant":      "acme",
            "environment": "staging",
        },
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    use std::collections::HashMap;

    let tags = HashMap::from([
        ("tenant".to_string(), "acme".to_string()),
        ("environment".to_string(), "staging".to_string()),
    ]);

    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".into(),
        tags: Some(tags),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    CreateOptions options = new CreateOptions().setImage("ubuntu:22.04");
    options.tags = Map.of("tenant", "acme", "environment", "staging"); // there is no setTags()
    Sandbox sandbox = client.create(options);
    ```
  </TabItem>
</Tabs>

## List only the sandboxes with certain tags

Pass tags to `list`. A sandbox is returned only if it has **every** tag you pass, with the same value. An empty tag map returns every sandbox your token can see, just like a plain `list`.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandboxes = await client.list({
      tags: { tenant: "acme", environment: "staging" },
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandboxes = client.list(tags={"tenant": "acme", "environment": "staging"})
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandboxes, err := client.List(ctx, microvm.WithTags(map[string]string{
        "tenant":      "acme",
        "environment": "staging",
    }))
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let tags = HashMap::from([
        ("tenant".to_string(), "acme".to_string()),
        ("environment".to_string(), "staging".to_string()),
    ]);

    let sandboxes = client.list_with_tags(&tags)?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    List<Sandbox> sandboxes = client.list(Map.of("tenant", "acme", "environment", "staging"));
    ```
  </TabItem>
</Tabs>

## Read the tags on a sandbox

Every sandbox that create, get and list return carries its tags.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    for (const sandbox of sandboxes) {
      console.log(sandbox.id, sandbox.tags?.tenant);
    }
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    for sandbox in sandboxes:
        tags = sandbox.to_dict().get("tags", {})
        print(sandbox.id, tags.get("tenant"))
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    for _, sandbox := range sandboxes {
        fmt.Println(sandbox.ID, sandbox.Tags["tenant"])
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    for sandbox in &sandboxes {
        let tenant = sandbox.data.tags.as_ref().and_then(|t| t.get("tenant"));
        println!("{} {:?}", sandbox.data.id, tenant);
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    for (Sandbox sandbox : sandboxes) {
        String tenant = sandbox.tags == null ? null : sandbox.tags.get("tenant");
        System.out.println(sandbox.id + " " + tenant);
    }
    ```
  </TabItem>
</Tabs>

A sandbox with no tags has no `tags` value at all. That is why the examples check for it first.

## Ideas for using tags

- **One view per customer.** Tag each sandbox with `tenant` when you create it. When a customer asks for their sandboxes, list with `tenant` set to their ID. Your token still controls access to the server; the tag only narrows the view.
- **Split by environment.** Combine `environment` (`staging` or `production`) with a `service` tag. A deploy pipeline can then find exactly the sandboxes it owns.
- **A "my sandboxes" page.** Tag each sandbox with `owner` set to the user's email. An internal dashboard can then show each person their own sandboxes.

## How the filter is sent

The SDKs send each tag as a query parameter of the form `tag.<key>=<value>`. For example, the list call above asks for `?tag.tenant=acme&tag.environment=staging`. The SDKs encode keys and values for you, so dots, slashes and spaces are safe.

The server reads every `tag.` parameter, skips any with an empty key, and requires all the rest to match. It ignores parameters that do not start with `tag.`, so new list options can be added later without breaking this one.
