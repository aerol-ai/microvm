An SDK is a library that lets your code talk to the AerolVM server. There is one for TypeScript, Python, Go, Rust and Java. They all do the same things, so you can pick whichever language you already use.

## Install the SDK

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

    ```bash
    npm install @aerol-ai/aerolvm-sdk
    ```
  </TabItem>
  <TabItem label="Python">

    ```bash
    pip install aerolvm-sdk
    ```
  </TabItem>
  <TabItem label="Go">
    ```bash
    go get github.com/aerol-ai/microvm/sdk/go/pkg/microvm@latest
    ```
  </TabItem>
  <TabItem label="Rust">
    ```bash
    cargo add aerolvm-sdk
    ```
  </TabItem>
  <TabItem label="Java">

## Tell the SDK where your server is

Every SDK needs two things:

| Setting | What it is | Default |
|---|---|---|
| `SB_API_URL` | The address of your AerolVM server. | `http://127.0.0.1:21212` |
| `SB_PAT_TOKEN` | The secret token you chose when you installed the server. | None. You must set it, or `SB_API_TOKEN`. |
| `SB_API_TOKEN` | The same as `SB_PAT_TOKEN`, for any credential: the server token, your own API token (`avm_…`), or a sign-in token from `aerolvm auth token`. `SB_PAT_TOKEN` wins if both are set. | None |
| `SB_TEAM` | With [access control](/enterprise/sso/) on, the team to act for when your credential belongs to several. | None: your first team |

The easiest way is to set them in your terminal before you run your code:

```bash
export SB_API_URL=http://localhost:21212
export SB_PAT_TOKEN=your-secret-pat
```

You can also pass them in code. Code values win over the terminal settings.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    import { MicroVM } from "@aerol-ai/aerolvm-sdk";

    const client = new MicroVM({
      apiUrl: "http://localhost:21212",
      patToken: "your-secret-pat",
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    from microvm import MicroVM

    client = MicroVM(
        api_url="http://localhost:21212",
        pat_token="your-secret-pat",
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    client, err := microvm.NewClientWithConfig(&sdktypes.MicroVMConfig{
        APIUrl:   "http://localhost:21212",
        PATToken: "your-secret-pat",
    })
    if err != nil {
        log.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust

    let client = Client::new(Some("http://localhost:21212"), Some("your-secret-pat"))?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java

    import ai.aerol.microvm.MicroVMConfig;

    MicroVMClient client = new MicroVMClient(
        new MicroVMConfig()
            .setApiUrl("http://localhost:21212")
            .setPatToken("your-secret-pat")
    );
    ```
  </TabItem>

<Aside type="caution">
Treat the token like a password. Do not commit it to Git or put it in code that runs in a browser. Read it from an environment variable or a secret manager instead.
</Aside>

| Error | Fix |
|---|---|
| `PAT token is required` | Set `SB_PAT_TOKEN` or `SB_API_TOKEN`, or pass the token in code. |
| `unauthorized` | The token does not match the one the server was installed with. |
| `Connection refused` | The server is not running, or `SB_API_URL` points to the wrong address. |

## When the server is busy

A busy server can turn a request away and say when to try again. It answers `503` when it is overloaded, and `429` when your code sends more than its fair share. Both answers can carry a `Retry-After` header: the number of seconds to wait, or a date and time.

Every SDK retries these for you, up to 3 times:

- It waits as long as `Retry-After` asks, never less.
- It adds up to a fifth more, at random, so many clients do not all come back at the same moment.
- It never waits more than 30 seconds for one retry. A longer ask is cut to 30 seconds.
- Without a `Retry-After`, it waits a short time that doubles on each try: about 200 ms, then 400 ms, then 800 ms.

To change the 30-second limit, set the retry option `maxRetryAfterMs` (`MaxRetryAfterMs` in Go, `max_retry_after_ms` in Rust). Set it to `0` to ignore `Retry-After` and always use the short waits.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    import { MicroVM } from "@aerol-ai/aerolvm-sdk";

    const controller = new AbortController();
    const client = new MicroVM({
      retry: { maxRetryAfterMs: 10_000 },
      // Optional: lets you stop this client's requests and waits.
      signal: controller.signal,
    });

    // Later, to stop everything this client is doing:
    controller.abort();
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    from microvm import MicroVM

    client = MicroVM(config={"retry": {"maxRetryAfterMs": 10000}})
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    maxWait := 10000
    client, err := microvm.NewClientWithConfig(&sdktypes.MicroVMConfig{
        Retry: &sdktypes.RetryConfig{MaxRetryAfterMs: &maxWait},
    })
    if err != nil {
        log.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    use aerolvm_sdk::{ApiVersion, Client, ClientConfig, RetryConfig};

    let client = Client::with_config(
        ClientConfig {
            retry: Some(RetryConfig {
                max_retry_after_ms: Some(10_000),
                ..Default::default()
            }),
            ..Default::default()
        },
        ApiVersion::V1,
    )?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.MicroVMClient;
    import ai.aerol.microvm.MicroVMConfig;
    import ai.aerol.microvm.model.RetryConfig;

    MicroVMClient client = new MicroVMClient(
        new MicroVMConfig()
            .setRetry(new RetryConfig().setMaxRetryAfterMs(10_000))
    );
    ```
  </TabItem>
</Tabs>

Each SDK stops a wait early in its own way:

| SDK | How to stop waiting |
|---|---|
| TypeScript | Pass `signal` to `MicroVM`. Aborting it ends the request and any wait. |
| Python | A signal handler that raises, such as Ctrl-C, ends the wait. |
| Go | Cancel the `ctx` you pass, or give it a deadline. |
| Rust | The client blocks, so a wait cannot be stopped. Lower `max_retry_after_ms` to keep waits short. |
| Java | Interrupt the thread, for example with `Future.cancel(true)`. |

## When a request fails

When the server says no, every SDK gives you an error that holds:

- **The status**, the HTTP number, such as `422` or `503`.
- **The code**, a short name such as `overloaded`. The server sends one for errors your code can act on.
- **The message**, words for a person to read.
- **The wait**, how long the server's `Retry-After` asked you to wait, when it sent one.

Use the code, not the message, to decide what your program does next. A code stays the same from one release to the next. A message can change.

Not every error has a code. Many errors are only meant for a person to read. An error page from a proxy in front of the server has no code either. For that page, the SDK makes the message from the status. The Rust SDK uses the page's text instead.

| SDK | Error type | Status | Code (when none) | Wait |
|---|---|---|---|---|
| TypeScript | `MicroVMApiError` | `status` | `code` (`undefined`) | `retryAfterMs` |
| Python | `MicroVMHTTPError` | `status_code` | `code` (`""`) | `retry_after`, in seconds |
| Go | `*microvm.APIError` | `StatusCode` | `Code` (`""`) | `RetryAfter` |
| Rust | `Error::Api(ApiError)` | `status()` | `code()` (`None`) | `retry_after()` |
| Java | `MicroVMApiException` | `getStatusCode()` | `getCode()` (`null`) | `getRetryAfter()` |

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    import { MicroVM, MicroVMApiError } from "@aerol-ai/aerolvm-sdk";

    const client = new MicroVM();

    try {
      const sandbox = await client.create({ image: "ubuntu:22.04" });
      console.log(`Created ${sandbox.id}`);
    } catch (err) {
      if (!(err instanceof MicroVMApiError)) throw err;
      console.error(`status ${err.status}, code ${err.code ?? "none"}: ${err.message}`);
      if (err.retryAfterMs !== undefined) {
        console.error(`The server asked to wait ${err.retryAfterMs} ms.`);
      }
    }
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    from microvm import MicroVM, MicroVMHTTPError

    client = MicroVM()

    try:
        sandbox = client.create(image="ubuntu:22.04")
        print(f"Created {sandbox.id}")
    except MicroVMHTTPError as err:
        print(f"status {err.status_code}, code {err.code or 'none'}: {err}")
        if err.retry_after is not None:
            print(f"The server asked to wait {err.retry_after} seconds.")
    ```
  </TabItem>
  <TabItem label="Go">
    ```go

    case errors.As(err, &apiErr):
        log.Printf("status %d, code %q: %s", apiErr.StatusCode, apiErr.Code, apiErr.Message)
        if apiErr.RetryAfter > 0 {
            log.Printf("The server asked to wait %s.", apiErr.RetryAfter)
        }
    case err != nil:
        log.Fatal(err)
    default:
        fmt.Println("Created", sandbox.ID)
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust

    let client = Client::new(None, None)?;

        image: "ubuntu:22.04".to_string(),

        Err(Error::Api(err)) => {
            eprintln!("status {}, code {:?}: {}", err.status(), err.code(), err.message());
            if let Some(wait) = err.retry_after() {
                eprintln!("The server asked to wait {:?}.", wait);
            }
        }
        Err(err) => eprintln!("create failed: {err}"),
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.MicroVMApiException;
    import ai.aerol.microvm.MicroVMClient;
    import ai.aerol.microvm.Sandbox;
    import ai.aerol.microvm.model.CreateOptions;

    MicroVMClient client = new MicroVMClient();

        Sandbox sandbox = client.create(new CreateOptions().setImage("ubuntu:22.04"));
        System.out.println("Created " + sandbox.id);
    } catch (MicroVMApiException e) {
        System.err.println("status " + e.getStatusCode() + ", code " + e.getCode() + ": " + e.getMessage());
        if (e.getRetryAfter() != null) {
            System.err.println("The server asked to wait " + e.getRetryAfter().toSeconds() + " seconds.");
        }
    }
    ```

Some codes you may see:

| Code | Status | What it means | What to do |
|---|---|---|---|
| `overloaded` | `503` | The node is running as many of this kind of request as it allows. | The SDK already tried again. Wait, then try later. |
| `rate_limited` | `429` | Your account or team sent more than its share of this kind of request. | Send fewer requests at once. |
| `egress_floor_not_ready` | `503` | The node has not yet set up the rules that keep sandboxes away from cloud metadata and blocked addresses. | Try again after the wait. The node fixes this by itself. |
| `node_guard_not_ready` | `503` | The node has not yet set up the rules that keep sandboxes away from the node's own services. | Try again after the wait. |
| `key_store_unavailable` | `503` | The server could not reach the key store that protects sandbox secrets. | Try again after the wait. |
| `key_revoked` | `503` | The key that protects sandbox secrets was turned off or deleted in the key store. | Ask the key's owner to restore it. |
| `network_policy_unenforced` | `501` | This node cannot enforce the network rules you asked for. | Drop the rules, or ask the operator to turn on the host firewall. |
| `idempotency_key_reused` | `422` | The create's idempotency key was already used with other options. | Send the first options again, or use a new key. See [Retry a create safely](/sandboxes/#retry-a-create-safely). |

In Rust SDK 0.8.0, `Error::Api` holds an `ApiError` instead of the text `"<status>: <message>"`. Errors the SDK finds itself, such as a missing argument, moved to `Error::Client`. Code that read the old text as a `String` no longer compiles, so the compiler shows each place to update.
