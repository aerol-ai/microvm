AerolVM is open source under the MIT license. It runs on your own servers, and every feature on this page is in the free download. This section is for teams taking AerolVM to production, and for companies that want to work with its maintainer.

## What you get

Each feature is marked **Default** (on with no setup), **You turn it on**, or **Proposed** (not built yet, open for discussion).

| Feature | Status | Learn more |
|---|---|---|
| Five runtimes: containers, gVisor, Firecracker microVMs, WebAssembly and V8 isolates | Containers by default. You turn on the others. | [Sandboxes](/sandboxes/) |
| Outbound network policy: block everything, or allow only named sites | You turn it on | [Network access](/network-access/) |
| Private by default: no one can reach a new sandbox until you share a port | Default | [Public URLs](/public-urls/) |
| API keys kept out of the sandbox with inject rules | You turn it on | [Advanced network rules](/advanced-network-rules/#keep-an-api-key-out-of-the-sandbox) |
| Encrypted environment variables, with every read recorded | Default | [Environment variables](/sandbox-env/) |
| Storage credentials that never enter the sandbox | Default | [External storage](/external-storage/) |
| A tamper-evident audit log | Default | [Evidence for your audit](/enterprise/audit-evidence/) |
| Audit export to a file, a webhook or S3 | You turn it on | [Audit](/enterprise/security-controls/#audit) |
| Clusters with failover and mutual TLS between servers | You turn it on | [Run it in production](/enterprise/deployment/) |
| AWS KMS for the secret copies a cluster keeps | You turn it on | [Secrets providers](/cluster-secrets/) |
| Metrics, traces, dashboards and alerts with runbooks | You turn it on | [Runbooks](/operational-runbooks/) |
| Signed releases with checksums, build provenance and a bill of materials | Default | [Release verification](https://github.com/aerol-ai/microvm/blob/main/RELEASE-VERIFICATION.md) |
| Single sign-on (SSO) for the API | Proposed | [Discuss](https://github.com/aerol-ai/microvm/discussions/647) |
| Scoped API tokens and roles | Proposed | [Discuss](https://github.com/aerol-ai/microvm/discussions/646) |
| Quotas per team | Proposed | [Discuss](https://github.com/aerol-ai/microvm/discussions/648) |
| The API caller's name in audit records | Proposed | [Discuss](https://github.com/aerol-ai/microvm/discussions/649) |
| Image signature checks | Proposed | [Discuss](https://github.com/aerol-ai/microvm/discussions/650) |

Need a proposed feature? Say so in [Ideas](https://github.com/aerol-ai/microvm/discussions/categories/ideas). A company can also [sponsor a feature](/enterprise/maintainer/) to get it built sooner. It is built in the open and ships to everyone.

## Security at a glance

| Question | Short answer | Details |
|---|---|---|
| What keeps a sandbox off the server? | The runtime. Containers share the server's kernel. gVisor and Firecracker put a stronger wall in between. | [Isolation](/enterprise/security-controls/#isolation) |
| What can a new sandbox reach? | The internet and your private network, until you set a policy. V8 isolates are the exception. | [Network](/enterprise/security-controls/#network) |
| Who can reach a new sandbox? | No one, until you share a port. | [Network](/enterprise/security-controls/#network) |
| Where do secrets live? | Encrypted on the server. Every time one is opened, a record is written. | [Secrets](/enterprise/security-controls/#secrets) |
| Can an AI agent leak an API key? | Not with an inject rule. The sandbox only ever holds a placeholder. | [Secrets](/enterprise/security-controls/#secrets) |
| Who can call the API? | Anyone with the server's API token. | [API access](/enterprise/security-controls/#api-access) |
| What gets recorded? | Every secret read, and the outbound connections the filter refuses. The records form a chain that shows tampering. | [Audit](/enterprise/security-controls/#audit) |
| What is out of scope? | The server itself, the kernel and hardware, and where your images come from. | [Known limits](/enterprise/responsibility/) |

## Evidence for a security review

[Evidence for your audit](/enterprise/audit-evidence/) lists everything a reviewer can collect. The main documents live in the repository:

- [Threat model](https://github.com/aerol-ai/microvm/blob/main/THREAT-MODEL.md): the trust boundaries and what each one protects.
- [Security assessment](https://github.com/aerol-ai/microvm/blob/main/SECURITY-ASSESSMENT.md): the problems that matter most, and where each one stands.
- [Security policy](https://github.com/aerol-ai/microvm/blob/main/SECURITY.md): how to report a vulnerability, with response times.
- [Release verification](https://github.com/aerol-ai/microvm/blob/main/RELEASE-VERIFICATION.md): how to check that a download is the official build.
