Every sandbox counts the bytes it receives and the bytes it sends. You can also give each direction a cap. When a sandbox reaches a cap, traffic in that direction stops until you raise it.

Use caps when a sandbox needs the internet but should not use too much of it, such as an agent that downloads files. You set caps at create, read the counters at any time, and raise or remove a cap while the sandbox runs.

To control *where* a sandbox can connect instead of *how much*, see [Block or allow the internet](/network-isolation/) and [Allow only some websites](/egress-domain-filtering/).

## Create a sandbox with caps

Both caps are optional. Leave one out, or pass `0`, to keep that direction unlimited. This sandbox can receive 1 GiB and send 5 GiB:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'ubuntu:22.04',
      networkBytesInLimit:  1 * 1024 * 1024 * 1024, // 1 GiB received
      networkBytesOutLimit: 5 * 1024 * 1024 * 1024, // 5 GiB sent
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'ubuntu:22.04',
        'networkBytesInLimit':  1 * 1024 * 1024 * 1024,
        'networkBytesOutLimit': 5 * 1024 * 1024 * 1024,
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:                "ubuntu:22.04",
        NetworkBytesInLimit:  1 << 30,
        NetworkBytesOutLimit: 5 << 30,
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".to_string(),
        network_bytes_in_limit:  Some(1 << 30),
        network_bytes_out_limit: Some(5 << 30),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.model.CreateOptions;

    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("ubuntu:22.04")
            .setNetworkBytesInLimit(1L << 30)
            .setNetworkBytesOutLimit(5L << 30)
    );
    ```
  </TabItem>
</Tabs>

| Option | What it does | Default |
|---|---|---|
| `networkBytesInLimit` | The most bytes the sandbox may receive in its lifetime. | `0` (unlimited) |
| `networkBytesOutLimit` | The most bytes the sandbox may send in its lifetime. | `0` (unlimited) |

## Read the counters

`getNetworkUsage` returns the counters, the caps, and whether a cap has been reached.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const usage = await sandbox.getNetworkUsage()
    console.log(usage.bytesIn, usage.bytesOut, usage.quotaExceeded)
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    usage = sandbox.get_network_usage()
    print(usage['bytesIn'], usage['bytesOut'], usage['quotaExceeded'])
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    usage, err := sandbox.GetNetworkUsage(ctx)
    if err != nil {
        return err
    }
    fmt.Println(usage.BytesIn, usage.BytesOut, usage.QuotaExceeded)
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let usage = sandbox.get_network_usage()?;
    println!("{} {} {}", usage.bytes_in, usage.bytes_out, usage.quota_exceeded);
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.model.NetworkUsage;

    NetworkUsage usage = sandbox.getNetworkUsage();
    System.out.println(usage.bytesIn + " " + usage.bytesOut + " " + usage.quotaExceeded);
    ```
  </TabItem>
</Tabs>

The fields below use the TypeScript, Python and Java names. Go capitalizes them (`BytesIn`), and Rust uses snake case (`bytes_in`).

| Field | What it means |
|---|---|
| `bytesIn` / `bytesOut` | Total bytes received and sent since the sandbox was created. |
| `bytesInLimit` / `bytesOutLimit` | The current caps. `0` means unlimited. |
| `quotaExceeded` | `true` once either direction reaches its cap. While it is `true`, traffic in the capped direction is dropped. |
| `quotaExceededAt` | When a cap was first reached, as an RFC 3339 time (like `2026-10-10T14:03:00Z`). Cleared when you raise the cap. |
| `lastSampledAt` | When the server last read the counters. Missing until the first reading, which can take up to one sampling period (10 seconds by default) after the server starts. |

## Raise or remove a cap while it runs

`setNetworkLimits` changes only the caps you pass. Pass a higher number to raise a cap, or `0` to remove it. Leave a cap out to keep it as it is.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    // Raise the sent-bytes cap to 20 GiB; leave the received cap alone.
    const usage = await sandbox.setNetworkLimits({
      networkBytesOutLimit: 20 * 1024 * 1024 * 1024,
    })

    // Remove the received-bytes cap (0 = unlimited).
    await sandbox.setNetworkLimits({ networkBytesInLimit: 0 })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    usage = sandbox.set_network_limits({
        'networkBytesOutLimit': 20 * 1024 * 1024 * 1024,
    })

    sandbox.set_network_limits({'networkBytesInLimit': 0})
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    out := int64(20) << 30
    usage, err := sandbox.SetNetworkLimits(ctx, sdktypes.SetNetworkLimitsOptions{
        NetworkBytesOutLimit: &out,
    })
    if err != nil {
        return err
    }

    zero := int64(0)
    if _, err := sandbox.SetNetworkLimits(ctx, sdktypes.SetNetworkLimitsOptions{
        NetworkBytesInLimit: &zero,
    }); err != nil {
        return err
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let usage = sandbox.set_network_limits(SetNetworkLimitsOptions {
        network_bytes_out_limit: Some(20 << 30),
        ..Default::default()
    })?;

    sandbox.set_network_limits(SetNetworkLimitsOptions {
        network_bytes_in_limit: Some(0),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.model.NetworkUsage;
    import ai.aerol.microvm.model.SetNetworkLimitsOptions;

    NetworkUsage usage = sandbox.setNetworkLimits(
        new SetNetworkLimitsOptions().setNetworkBytesOutLimit(20L << 30)
    );

    sandbox.setNetworkLimits(
        new SetNetworkLimitsOptions().setNetworkBytesInLimit(0L)
    );
    ```
  </TabItem>
</Tabs>

If the new cap is above the current count, traffic flows again at once. If it is still below, the block stays. The counters never go down, so the block lasts until you raise the cap above the count or destroy the sandbox.

## Good to know

- **Caps are checked on each reading.** The server reads the counters every 10 seconds by default. A fast transfer can go past a cap before the block starts.
- **Received bytes are counted after they arrive.** A cap stops further traffic. It cannot undo bytes the sandbox already received.
- **A cap does not undo block-all.** Raising or removing the sent-bytes cap never lifts `networkBlockAll`. Both use the same block.
- **IPv4 only.** The counters and caps cover IPv4 traffic, as with [Block or allow the internet](/network-isolation/).
- **Linux servers only.** On Docker sandboxes the block is applied by the server's firewall, which runs only on Linux.
- **Not on Firecracker yet.** A Firecracker sandbox refuses byte caps with `501`, at create and with `setNetworkLimits`.

## For server operators

| Setting | What it does | Default |
|---|---|---|
| `SB_NETSTATS_POLL_INTERVAL` | How often the server reads every sandbox's byte counters and checks the caps. | `10s` |
