AerolVM is a server program that you run yourself. Your app talks to it through an SDK. You can run the server in four places, and your SDK code is the same in all of them. Only the server address and token change.

Most people start on their own computer. Move to a server when your sandboxes need web links that other people can open. Move to a cluster (a group of servers that work as one) when one server is not enough. If your team already runs Kubernetes, install AerolVM there with Helm instead.

## Compare the setups

| | Your computer | One server | A cluster | Your Kubernetes |
|---|---|---|---|---|
| **Best for** | Trying AerolVM and building your app | Real use, with public web links | Many sandboxes, and staying up when a server fails | Teams that already run Kubernetes |
| **Runs on** | macOS or Linux | One Ubuntu or Debian server | Three or more Linux machines, on any cloud | EKS, AKS, GKE, or kind on a laptop |
| **You need** | Docker. On a Mac, Docker Desktop or OrbStack. | A domain name managed by Cloudflare | A domain name managed by Cloudflare, and a private network between the machines | Helm and cluster-admin. For production, cert-manager too. |
| **How you install** | One command | One command | One command on each machine. Or Terraform makes it on AWS. | `helm install` |
| **Server address** | `http://localhost:21212` | `https://sandbox.example.com` (your domain) | `https://sandbox.example.com` (your domain) | Your domain, or a port-forward |
| **Public web links for sandboxes** | No | Yes, under your domain | Yes, under your domain | Yes, under your domain |
| **HTTPS** | No | Yes, set up for you | Yes, set up for you | Yes, with cert-manager |
| **Kinds of sandbox** | Containers | Containers, plus gVisor, Firecracker, WebAssembly, V8 isolates and GPUs if you turn them on | Same as one server | Containers and gVisor, plus Firecracker, WebAssembly and V8 isolates if you turn them on |
| **If a server fails** | Not a concern | Nothing takes over | Sandboxes that ask for it are recreated on a healthy server | In cluster mode, as for a cluster |

## Which one should I pick?

- **You want to try AerolVM or build your app.** Use [your computer](/getting-started/local-setup/). The [Quickstart](/quick-start/) does this in about five minutes.
- **People on the internet need to open a sandbox's web page.** Use [one server](/getting-started/single-node-setup/). It gives each sandbox a link like `https://<sandbox-id>-3000.sandbox.example.com`.
- **You run more sandboxes than one server can hold, or you cannot afford downtime.** Use a [cluster](/cluster/).
- **Your team already runs Kubernetes.** Install with the [Helm chart](/kubernetes/). Single mode takes about five minutes on any cluster.

## Good to know

- **Your code does not change when you move.** Set `SB_API_URL` to the new server's address and `SB_PAT_TOKEN` to its token.
- **Sandboxes do not move with you.** Each setup has its own sandboxes. Create new ones on the new setup.
- **The computer setup is for development only.** It does not apply network rules. On a Mac, it also ignores CPU, memory and disk limits. See [Install on your computer](/getting-started/local-setup/#good-to-know).
