In this tutorial you start a Chromium browser inside a sandbox and let a user drive it from a normal web page. Your user clicks a link, sees a browser window in their tab, and browses the web with it. When they are done, you delete the sandbox and everything they did is gone.

This is called browser isolation. Risky pages, downloads and tracking all stay inside the sandbox, never on the user's computer or your servers.

## How it works

The sandbox runs a small Linux desktop. Each part has one job:

| Part | What it does |
|---|---|
| Xvfb | A fake screen in memory, since the sandbox has no monitor |
| Openbox | A simple window manager that draws the browser window |
| Chromium | The browser itself (the open-source base of Google Chrome) |
| x11vnc | Shares the fake screen using VNC, a standard remote-desktop protocol |
| websockify and noVNC | Turn that VNC stream into a web page on port 6080 |

You share port 6080 with `exposePort`. The user opens the link and sees the desktop.

## What you need

- **An AerolVM server.** For a link that other people can open, [install on a server](/getting-started/single-node-setup/) with a domain. On [your computer](/getting-started/local-setup/), the link works only on that computer.
- **`SB_API_URL` and `SB_PAT_TOKEN`** set in your terminal, as shown in [SDK setup](/sdk-setup/).
- **An SDK** for your language. See [SDK setup](/sdk-setup/).

The steps below show each call in all five languages. The [examples repository](https://github.com/aerol-ai/aerolvm-examples/tree/main/customer-facing/secure-burner-browser) has the whole thing as one TypeScript program, `index.ts`. It also waits for each part to be ready and writes `secure-burner-browser.json` with the IDs and links.

### Step 1: Save the setup script

Save this as `bootstrap.sh` on your computer. It runs inside the sandbox. It installs the desktop parts and writes a second script, `run-browser-isolation.sh`, that starts them.

```sh
#!/bin/sh
set -eu
export DEBIAN_FRONTEND=noninteractive
apt-get update
apt-get install -y --no-install-recommends \
  ca-certificates \
  chromium \
  novnc \
  openbox \
  websockify \
  x11-utils \
  x11vnc \
  xvfb
rm -rf /var/lib/apt/lists/*
mkdir -p /workspace/browser-isolation/logs /workspace/browser-isolation/profile
cat > /workspace/browser-isolation/run-browser-isolation.sh <<'EOF'
#!/bin/sh
set -eu
WORKDIR=/workspace/browser-isolation
PORT="${NOVNC_PORT:-6080}"
DISPLAY_NUM="${DISPLAY_NUM:-99}"
SCREEN_GEOMETRY="${SCREEN_GEOMETRY:-1440x900x24}"
WINDOW_SIZE="${WINDOW_SIZE:-1440,900}"
START_URL="${START_URL:-about:blank}"
export DISPLAY=":${DISPLAY_NUM}"
LOGDIR="${WORKDIR}/logs"
PROFILE_DIR="${WORKDIR}/profile"
mkdir -p "${LOGDIR}" "${PROFILE_DIR}"

cleanup() {
  kill "${WEBSOCKIFY_PID:-}" "${X11VNC_PID:-}" "${CHROMIUM_PID:-}" "${OPENBOX_PID:-}" "${XVFB_PID:-}" 2>/dev/null || true
}
trap cleanup EXIT INT TERM

Xvfb "${DISPLAY}" -screen 0 "${SCREEN_GEOMETRY}" >"${LOGDIR}/xvfb.log" 2>&1 &
XVFB_PID=$!

for _ in $(seq 1 30); do
  if xdpyinfo -display "${DISPLAY}" >/dev/null 2>&1; then
    break
  fi
  sleep 1
done

if ! xdpyinfo -display "${DISPLAY}" >/dev/null 2>&1; then
  echo 'Xvfb did not become ready in time' >&2
  exit 1
fi

openbox >"${LOGDIR}/openbox.log" 2>&1 &
OPENBOX_PID=$!

chromium --no-sandbox --disable-dev-shm-usage --disable-gpu --no-first-run --no-default-browser-check --user-data-dir="${PROFILE_DIR}" --window-size="${WINDOW_SIZE}" "${START_URL}" >"${LOGDIR}/chromium.log" 2>&1 &
CHROMIUM_PID=$!

x11vnc -display "${DISPLAY}" -forever -shared -nopw -rfbport 5900 -listen 0.0.0.0 >"${LOGDIR}/x11vnc.log" 2>&1 &
X11VNC_PID=$!

echo "noVNC listening on http://0.0.0.0:${PORT}/vnc.html"
websockify --web=/usr/share/novnc/ 0.0.0.0:"${PORT}" localhost:5900 >"${LOGDIR}/websockify.log" 2>&1 &
WEBSOCKIFY_PID=$!
wait "${WEBSOCKIFY_PID}"
EOF
chmod +x /workspace/browser-isolation/run-browser-isolation.sh
echo 'browser isolation bootstrap complete'
```

You can change the screen size and the first page with the `SCREEN_GEOMETRY`, `WINDOW_SIZE` and `START_URL` settings. Step 6 sets `START_URL`.

### Step 7: Open the browser

Add `vnc.html?autoconnect=1&resize=remote&reconnect=1` to the end of the link from step 5. Put a `/` between them if the link does not already end in one. For example:

```text
https://<sandbox-id>-6080.<your-domain>/vnc.html?autoconnect=1&resize=remote&reconnect=1
```

Open it in your browser. After a few seconds you see Chromium showing `https://example.com`. Click and type in it like any browser.

## Clean up

Delete the sandbox when the user is done with `sandbox.destroy()`, or run `aerolvm destroy <sandbox-id>` with the [aerolvm CLI](/cli/). The full `index.ts` program also sets `lifecycle` so the sandbox stops after 15 idle minutes and deletes itself after 20.

## Good to know

<Aside type="caution">
The desktop has no password. Anyone with the link can see and control the browser. Put your own sign-in and access checks in front of the link before you give it to users.
</Aside>

- **The sandbox is the wall, not Chromium.** The script starts Chromium with `--no-sandbox`, which turns off Chromium's own sandbox. The AerolVM sandbox keeps the browser away from your machine instead.
- **It needs the internet.** The browser is meant to visit public websites, so do not block outbound traffic for this sandbox.
- **It uses VNC, not video streaming.** noVNC works well for browsing and remote desktops. It is not the fastest possible way to stream a screen.
- **gVisor may work, but test first.** The example uses the default container setup because the desktop parts are known to work there. For a stronger wall, test your image and desktop under `runtime: "gvisor"` before you switch real users to it. The full `index.ts` program reads `SANDBOX_RUNTIME=gvisor` to try this.
