In this tutorial you put a coding interview app online. A candidate writes code in the browser, picks a language and clicks **Run Code**. The app runs that code in a brand-new sandbox, shows the output and deletes the sandbox.

Every answer runs alone, so one candidate's code can never see or break another's. If the code crashes or loops forever, only its own sandbox is affected.

## How it works

The system has two parts:

1. **A host script, `index.ts`.** It runs on your computer. It starts the interview app in a sandbox, waits for it to be ready and prints its public link.
2. **The interview app, `server.ts`.** It runs inside that sandbox. It serves the code editor page. When a candidate clicks **Run Code**, it creates a second, short-lived sandbox for that one run.

So sandboxes create other sandboxes. The app does this with the same SDK you use, through the AerolVM server's API.

## What you need

- **An AerolVM server.** For a link that candidates can open, [install on a server](/getting-started/single-node-setup/) with a domain. On [your computer](/getting-started/local-setup/), the link works only on that computer.
- **`SB_API_URL` and `SB_PAT_TOKEN`** set in your terminal, as shown in [SDK setup](/sdk-setup/).
- **`SANDBOX_API_URL`**: the address of your AerolVM server as seen from inside a sandbox. See the caution below.
- **Node.js 20 or newer.**

<Aside type="caution">
Inside a sandbox, `127.0.0.1` means the sandbox itself, not your AerolVM server. If the app gets `http://127.0.0.1:21212`, every **Run Code** click fails. Set `SANDBOX_API_URL` to an address that works from inside a sandbox:

- On a server with a domain, use its public address: `https://<your-domain>`.
- On a Mac local install, `http://host.docker.internal:21212` worked in our tests.
</Aside>

### Step 1: Set up a project

```bash
mkdir coding-interview && cd coding-interview
npm init -y
npm pkg set type=module
npm install @aerol-ai/aerolvm-sdk
```

### Step 2: Save the host script

Save this as `index.ts`. It starts the app from a ready-made image, `ghcr.io/aerol-ai/aerolvm-examples-interview-app:latest`. The app's own code is in the [examples repository](https://github.com/aerol-ai/aerolvm-examples/tree/main/customer-facing/edtech-coding-interviews).

```ts
import { MicroVM } from "@aerol-ai/aerolvm-sdk";
import { writeFile } from "node:fs/promises";
import { setTimeout as delay } from "node:timers/promises";

const patToken = process.env.SB_PAT_TOKEN;
const apiUrl = process.env.SB_API_URL ?? "http://127.0.0.1:21212";
// The app calls the AerolVM API from inside its sandbox, where 127.0.0.1 is
// the sandbox itself. SANDBOX_API_URL is the server's address as seen from there.
const sandboxApiUrl = process.env.SANDBOX_API_URL ?? apiUrl;
const imageName =
  process.env.IMAGE_NAME ??
  "ghcr.io/aerol-ai/aerolvm-examples-interview-app:latest";

if (!patToken) {
  throw new Error("Set SB_PAT_TOKEN before running this example.");
}

async function main() {
  const client = new MicroVM({ apiUrl, patToken });

  // 1. Create the parent sandbox from the pre-built interview-app image.
  //    Pass SB_PAT_TOKEN and SB_API_URL so the app can create child sandboxes.
  const sandbox = await client.create({
    image: imageName,
    cpu: 1,
    memoryMB: 1024,
    env: {
      SB_PAT_TOKEN: patToken!,
      SB_API_URL: sandboxApiUrl,
      PORT: "3000",
    },
  });

  console.log(`Sandbox created: ${sandbox.id}`);

  // 2. Wait for the Express server to be healthy.
  for (let attempt = 0; attempt < 20; attempt++) {
    const result = await sandbox.exec({
      command:
        'curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000',
      timeoutSeconds: 5,
    });
    if (result.exitCode === 0) break;
    await delay(1_000);
  }

  // 3. Expose port 3000 and print the public URL.
  const exposure = await sandbox.exposePort(3000);
  console.log(`Interview App is live at: ${exposure.url}`);

  await writeFile(
    "interview-app-deployment.json",
    `${JSON.stringify({ sandboxID: sandbox.id, appUrl: exposure.url }, null, 2)}\n`,
  );
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

### Step 3: Run it

```bash
export SANDBOX_API_URL=https://<your-domain>
npx tsx index.ts
```

You should see:

```text
Sandbox created: sb-...
Interview App is live at: https://<sandbox-id>-3000.<your-domain>
```

The script also writes `interview-app-deployment.json` with the sandbox ID and the link.

### Step 4: Try it

1. Open the link in your browser.
2. Pick a language from the menu.
3. Write some code, or keep the sample, and click **Run Code**.

The output appears in the terminal panel. By then, the sandbox that ran it is already gone.

## What happens on each Run Code click

The app follows the same five steps for every run:

1. It creates a sandbox from the image for the chosen language, with half a CPU core and 512 MB of memory.
2. It uploads the candidate's code as a file, such as `/workspace/main.py`.
3. It runs the language's command, for example `python3 /workspace/main.py`.
4. It sends the output, errors and exit code back to the browser.
5. It deletes the sandbox, even when the run fails. As a backup, the sandbox also deletes itself after 5 idle minutes.

The app supports these 10 languages. Each one is a standard public image, which the server downloads the first time it is used.

| Language | Image |
|---|---|
| Python | `python:3.11-slim` |
| JavaScript | `node:20-slim` |
| Rust | `rust:1.75-slim` |
| Go | `golang:1.21-alpine` |
| C++ | `gcc:13` |
| Java | `openjdk:21-slim` |
| Ruby | `ruby:3.2-slim` |
| PHP | `php:8.2-cli` |
| Bash | `alpine:3.19` |
| Perl | `perl:5.38-slim` |

## Clean up

The app sandbox keeps running until you delete it. Find its ID in `interview-app-deployment.json`, then run `aerolvm destroy <sandbox-id>` with the [aerolvm CLI](/cli/). You can also call `sandbox.destroy()` from your code.

## Good to know

- **The app sandbox holds your token.** It needs `SB_PAT_TOKEN` to create sandboxes. Candidate code never runs there. It runs only in the short-lived sandboxes, which get no token.
- **The first run of each language is slow.** The server has to download that language's image once. Later runs reuse it.
- **To change the app,** build your own image from the `interview-app` folder in the examples repository. Then set `IMAGE_NAME` to your image before you run the host script.
