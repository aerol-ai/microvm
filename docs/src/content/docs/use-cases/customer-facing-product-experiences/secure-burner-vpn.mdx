In this tutorial you give a user a throwaway proxy for their browser. A user clicks a button in your product, and you create one sandbox for them. They point Chrome at it, and every page they open is fetched by the sandbox instead of their own computer. When they are done, you delete the sandbox and the proxy is gone.

It works like a burner VPN for one browser window. It is not a full VPN: only the Chrome window you start with the proxy setting uses it. Other apps on the computer are not affected.

## How it works

The sandbox runs one small Node.js app, from a ready-made image, that does two jobs:

| Job | Port in the sandbox | Public address |
|---|---|---|
| A dashboard web page with connection steps and live traffic numbers | 3000 | `https://...` link |
| A SOCKS5 proxy, a standard proxy type that browsers support | 1080 | `tcp://<host>:<port>` |

A host script on your computer creates the sandbox, waits for the dashboard, and shares both ports. Then it writes the proxy address back into the sandbox, so the dashboard can show it.

## What you need

- **An AerolVM server.** For addresses that other people can reach, [install on a server](/getting-started/single-node-setup/) with a domain. On [your computer](/getting-started/local-setup/), the addresses work only on that computer.
- **`SB_API_URL` and `SB_PAT_TOKEN`** set in your terminal, as shown in [SDK setup](/sdk-setup/). The script also reads them from a `.env` file.
- **Node.js 20 or newer**, and Google Chrome.

### Step 1: Set up a project

```bash
mkdir burner-vpn && cd burner-vpn
npm init -y
npm pkg set type=module
npm install @aerol-ai/aerolvm-sdk dotenv
```

### Step 2: Save the script

Save this as `index.ts`. The [examples repository](https://github.com/aerol-ai/aerolvm-examples/tree/main/customer-facing/burner-vpn) has the same script and the app that runs inside the sandbox (`vpn-app/server.ts`).

```ts
import { MicroVM } from '@aerol-ai/aerolvm-sdk'
import * as dotenv from 'dotenv'
import { writeFile } from 'node:fs/promises'
import path from 'node:path'
import { setTimeout as delay } from 'node:timers/promises'
import { fileURLToPath } from 'node:url'

dotenv.config()

const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)

const patToken = process.env.SB_PAT_TOKEN
const apiUrl = process.env.SB_API_URL ?? 'http://127.0.0.1:21212'
const imageName =
  process.env.IMAGE_NAME ?? 'ghcr.io/aerol-ai/aerolvm-examples-burner-vpn:latest'

if (!patToken) {
  throw new Error('Set SB_PAT_TOKEN before running this example.')
}

async function withRetry<T>(label: string, fn: () => Promise<T>, attempts = 5): Promise<T> {
  let lastError: unknown

  for (let attempt = 0; attempt < attempts; attempt += 1) {
    try {
      return await fn()
    } catch (error) {
      lastError = error
      const waitMs = Math.min(8000, 1000 * 2 ** attempt)
      console.log(`${label} failed on attempt ${attempt + 1}/${attempts}; retrying in ${waitMs}ms`)
      await delay(waitMs)
    }
  }

  throw lastError
}

async function main() {
  const dashboardPort = 3000
  const socksPort = 1080
  const client = new MicroVM({ apiUrl, patToken })

  const sandbox = await client.create({
    image: imageName,
    cpu: 1,
    memoryMB: 1024,
    env: {
      PORT: String(dashboardPort),
      SOCKS_PORT: String(socksPort),
    },
  })

  for (let attempt = 0; attempt < 20; attempt += 1) {
    const result = await sandbox.exec({
      command: `node -e "const req = require('http').get('http://127.0.0.1:${dashboardPort}', (res) => process.exit(res.statusCode === 200 ? 0 : 1)); req.on('error', () => process.exit(1)); req.setTimeout(2000, () => process.exit(1));"`,
      timeoutSeconds: 5,
    })

    if (result.exitCode === 0) {
      break
    }

    await delay(1000)
  }

  const dashboardExposure = await withRetry('dashboard exposePort', () =>
    sandbox.exposePort(dashboardPort),
  )

  const socksExposure = await withRetry('socks exposePort', () =>
    sandbox.exposePort(socksPort, { protocol: 'tcp' }),
  )

  const dashboardUrl = dashboardExposure.url
  const socksUrl = new URL(socksExposure.url)
  const socksProxyHost = socksUrl.hostname
  const socksProxyPort = Number.parseInt(socksUrl.port, 10)
  const socksProxyEndpoint = `${socksProxyHost}:${socksProxyPort}`
  // A separate profile makes Chrome start a new browser that uses the proxy.
  // Without it, an already-open Chrome takes over and ignores these flags.
  const chromeLaunchCommand =
    `open -na "Google Chrome" --args --user-data-dir=/tmp/burner-vpn-profile ` +
    `--proxy-server="socks5://${socksProxyEndpoint}" ` +
    `--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE ${socksProxyHost}"`

  const runtimeConfig = {
    proxyScheme: 'socks5',
    authMode: 'none',
    dashboardUrl,
    socksProxyEndpoint,
    socksProxyHost,
    socksProxyPort,
    chromeLaunchCommand,
  }

  await sandbox.uploadFile(
    '/app/public/runtime-config.json',
    `${JSON.stringify(runtimeConfig, null, 2)}\n`,
  )

  await writeFile(
    path.join(__dirname, 'burner-vpn-deployment.json'),
    `${JSON.stringify(
      {
        sandboxID: sandbox.id,
        ...runtimeConfig,
      },
      null,
      2,
    )}\n`,
  )

  console.log(`Dashboard URL: ${dashboardUrl}`)
  console.log(`SOCKS5 endpoint: ${socksProxyEndpoint}`)
  console.log(`Chrome launch command: ${chromeLaunchCommand}`)
}

main().catch((error) => {
  console.error(error)
  process.exitCode = 1
})
```

What the script does, in order:

1. Creates a sandbox from the ready-made image, with 1 CPU core and 1 GB of memory.
2. Checks the dashboard every second, up to 20 times, until it answers.
3. Shares port 3000 as an HTTPS link and port 1080 as a raw TCP address. `withRetry` tries each call again, up to 5 times, if it fails.
4. Builds the Chrome command and uploads the settings to `/app/public/runtime-config.json`, where the dashboard reads them.
5. Saves everything to `burner-vpn-deployment.json` and prints it.

### Step 3: Run it

```bash
npx tsx index.ts
```

You should see:

```text
Dashboard URL: https://<sandbox-id>-3000.<your-domain>
SOCKS5 endpoint: <host>:<port>
Chrome launch command: open -na "Google Chrome" --args --user-data-dir=/tmp/burner-vpn-profile --proxy-server="socks5://<host>:<port>" --host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE <host>"
```

### Step 4: Start Chrome through the proxy

Copy the Chrome command the script printed and run it. On macOS it looks like this, with your own host and port:

```bash
open -na "Google Chrome" --args --user-data-dir=/tmp/burner-vpn-profile --proxy-server="socks5://HOST:PORT" --host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE HOST"
```

What each setting does:

- `--user-data-dir` starts a separate Chrome, with its own empty profile, so your normal browsing is not mixed in.
- `--proxy-server` sends that window's traffic through the sandbox's SOCKS5 proxy.
- `--host-resolver-rules` stops Chrome from looking up website names on your own computer. So those lookups also go through the proxy.

On Windows or Linux, start Chrome from a terminal with the same three settings.

### Step 5: Try it

Browse in the new Chrome window. Sites now see the server's internet address, not yours. Open the dashboard link to see how many connections are open and how much data has passed through.

## Clean up

This script sets no idle time, so the sandbox runs until you delete it. Find its ID in `burner-vpn-deployment.json`, then run `aerolvm destroy <sandbox-id>` with the [aerolvm CLI](/cli/). To have it deleted automatically, add a `lifecycle` setting to `client.create()`. See [Images, resources and lifecycle](/environment/).

## Good to know

<Aside type="caution">
The proxy has no password. Anyone who finds its address and port can send their traffic through your server. Give each user their own sandbox, and delete it as soon as they are done.
</Aside>

- **Why no password?** Chrome supports SOCKS5 proxies, but not SOCKS5 user names and passwords. So the example runs the proxy with `authMode: 'none'`. If you need a password, build an HTTP or HTTPS proxy instead.
- **How safe is it?** It keeps risky browsing traffic off the user's computer, and you can throw it away. How strong it is still depends on your image, your sandbox settings and your idle times. Call it a sandbox-isolated burner proxy, not a perfect VPN.

## For server operators

The SOCKS5 address uses a port from the server's TCP port pool, `22000` to `23000` by default. The firewall must allow inbound traffic on that range. The installer does not open it for you. See [TCP and TLS ports](/tcp-ports/).
