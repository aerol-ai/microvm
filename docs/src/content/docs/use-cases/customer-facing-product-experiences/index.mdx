In these tutorials, the sandbox is part of your product. A user clicks a button, and your backend creates a sandbox just for them. That sandbox then runs their app, their database, their code or their browser.

Each tutorial has working code that you can copy and run.

## The pattern behind all of them

1. **Create a sandbox when the user acts.** For example, when they open a workspace or click "Run".
2. **Upload the files it needs.** Starter code, a generated project or a config file.
3. **Start the program.** Use a command for short jobs. Use a session for programs that keep running, such as a web server.
4. **Share a port.** This gives the program a public link your user can open.
5. **Stop or delete the sandbox when it is idle.** A lifecycle setting can do this for you.

## The features they use

| Feature | What it does | Learn more |
|---|---|---|
| `client.create()` | Starts a new sandbox for one user or one task. | [Create and manage](/sandboxes/) |
| `sandbox.exposePort(port)` | Gives a web server inside the sandbox a public link. | [Share a web app](/preview/) |
| `exposePort(port, { protocol: "tcp" })` | Gives a database or other non-web program a public address and port. | [TCP and TLS ports](/tcp-ports/) |
| `sandbox.createSession()` | Keeps a program running after your script ends. | [Terminal sessions](/sessions/) |
| `runtime: "gvisor"` | Adds an extra wall between user code and your server. | [gVisor](/gvisor-sandbox/) |
| `networkBlockAll: true` | Cuts the sandbox off from the internet. | [Block or allow the internet](/network-isolation/) |
| `lifecycle` | Stops or deletes a sandbox after a set idle time. | [Images, resources and lifecycle](/environment/) |
