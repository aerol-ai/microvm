---
title: One sandbox per workspace
description: Give each workspace in your app its own sandbox that you can preview, stop and start again without losing files.
---

In this tutorial you tie a sandbox to each workspace in your product. When a user creates a workspace, you create a sandbox for it. The sandbox holds the workspace's files and serves a preview of them.

Each workspace's sandbox is separate. You can stop it when the user leaves, start it again when they come back, and delete it when the workspace is deleted. Stopping and starting keeps the files.

## Match workspace events to SDK calls

| When the user... | Call | What happens |
|---|---|---|
| Creates a workspace | `client.create()` | A new sandbox starts, just for this workspace. |
| Opens a preview | `sandbox.exposePort(3000)` | Port 3000 gets a public link. |
| Leaves for a while | `sandbox.stop()`, or `lifecycle.stopIfIdleFor` | The sandbox stops. Files stay on disk. |
| Comes back | `sandbox.start()` | The sandbox starts again with the same files. |
| Deletes the workspace | `sandbox.destroy()`, or `lifecycle.destroyIfIdleFor` | The sandbox and its files are deleted. |

## What you need

- **An AerolVM server.** For a preview link other people can open, [install on a server](/getting-started/single-node-setup/) with a domain. On [your computer](/getting-started/local-setup/), the link works only on that computer.
- **`SB_API_URL` and `SB_PAT_TOKEN`** set in your terminal, as shown in [SDK setup](/sdk-setup/).
- **Node.js 20 or newer.**

### Step 1: Set up a project

```bash
mkdir workspace-sandbox && cd workspace-sandbox
npm init -y
npm pkg set type=module
npm install @aerol-ai/aerolvm-sdk
```

### Step 2: Save the script

Save this as `index.ts`. It needs no other settings.

```ts
import { MicroVM } from "@aerol-ai/aerolvm-sdk";
import { writeFile } from "node:fs/promises";

const apiUrl = process.env.SB_API_URL ?? "http://127.0.0.1:21212";
const patToken = process.env.SB_PAT_TOKEN;

if (!patToken) {
  throw new Error("Set SB_PAT_TOKEN before running this example.");
}

const workspaceID = "workspace-demo-001";
const userID = "user-demo-001";
const seedFiles = [
  {
    path: "README.md",
    contents: `# Workspace demo\n\nThis file proves that workspace state survives stop and start.\n`,
  },
  {
    path: "index.html",
    contents: `<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Workspace Preview</title>
  </head>
  <body>
    <h1>Workspace preview</h1>
    <p>This page is served from a per-workspace AerolVM sandbox.</p>
  </body>
</html>
`,
  },
];

async function main() {
  const client = new MicroVM({ apiUrl, patToken });
  const sandbox = await client.create({
    image: "python:3.12-bookworm",
    cpu: 2,
    memoryMB: 2048,
    diskGB: 12,
    env: {
      WORKSPACE_ID: workspaceID,
      USER_ID: userID,
    },
    lifecycle: {
      stopIfIdleFor: 30 * 60 * 1_000_000_000,
      destroyIfIdleFor: 24 * 60 * 60 * 1_000_000_000,
    },
  });

  await sandbox.exec("mkdir -p /workspace/app");
  await Promise.all(
    seedFiles.map((file) =>
      sandbox.uploadFile(`/workspace/app/${file.path}`, file.contents),
    ),
  );

  const previewSession = await sandbox.createSession({
    name: "workspace-preview",
    command: "python3 -m http.server 3000 --directory /workspace/app",
    workDir: "/workspace/app",
  });

  await new Promise((resolve) => setTimeout(resolve, 2000));
  const initialPreviewURL = (await sandbox.exposePort(3000)).url;

  await sandbox.stop();
  await sandbox.start();
  await new Promise((resolve) => setTimeout(resolve, 2000));

  const persistedReadme = await sandbox.exec({
    command: "cat /workspace/app/README.md",
    timeoutSeconds: 10,
  });

  const resumedPreviewSession = await sandbox.createSession({
    name: "workspace-preview-resumed",
    command: "python3 -m http.server 3000 --directory /workspace/app",
    workDir: "/workspace/app",
  });

  await new Promise((resolve) => setTimeout(resolve, 2000));
  const resumedPreviewURL = (await sandbox.exposePort(3000)).url;

  const payload = {
    sandboxID: sandbox.id,
    previewSessionID: previewSession.id,
    resumedPreviewSessionID: resumedPreviewSession.id,
    initialPreviewURL,
    resumedPreviewURL,
    persistedReadme: persistedReadme.stdout,
  };

  await writeFile(
    "one-click-user-sandbox.json",
    `${JSON.stringify(payload, null, 2)}\n`,
  );

  console.log(JSON.stringify(payload, null, 2));
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

What the script does, in order:

1. Creates a sandbox with 2 CPU cores, 2 GB of memory and 12 GB of disk. It passes the workspace and user IDs in as environment variables.
2. Uploads two starter files, a `README.md` and an `index.html`.
3. Starts a small web server in a session and shares port 3000 as the preview link. A session is a program that keeps running after your call returns.
4. Stops the sandbox and starts it again, as if the user left and came back.
5. Reads `README.md` again, to show the files survived.
6. Starts the web server again in a new session and asks for the preview link again.

### Step 3: Run it

```bash
npx tsx index.ts
```

The script prints this and saves it to `one-click-user-sandbox.json`:

```text
{
  "sandboxID": "sb-...",
  "previewSessionID": "ses-...",
  "resumedPreviewSessionID": "ses-...",
  "initialPreviewURL": "https://<sandbox-id>-3000.<your-domain>",
  "resumedPreviewURL": "https://<sandbox-id>-3000.<your-domain>",
  "persistedReadme": "# Workspace demo\n\nThis file proves that workspace state survives stop and start.\n"
}
```

Both preview links are the same. Open one to see the workspace preview page.

## Clean up

The sandbox stops after 30 idle minutes and deletes itself after 24 idle hours. Durations in TypeScript are in nanoseconds. To delete it now, run `aerolvm destroy <sandbox-id>` with the [aerolvm CLI](/cli/), or call `sandbox.destroy()`.

## Good to know

- **Programs do not survive a stop.** Files stay, but sessions end when the sandbox stops. That is why the script starts the web server again after `start()`.
- **The preview link stays the same.** Asking for the same port again returns the link it already has.
- **Find a workspace's sandbox later** by giving it a `name`, such as the workspace ID, and looking it up with `client.getByName()`. You can also label it with tags. See [Create and manage](/sandboxes/) and [Tags](/sandbox-tags/).
