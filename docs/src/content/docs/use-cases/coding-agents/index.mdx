A coding agent is an AI program that reads code, edits files and runs commands. It needs a computer to do that. A sandbox gives it one: the agent can install tools and run tests there without touching your machine.

Each project below runs Claude Code, Anthropic's coding agent, on a real GitHub repository. Claude Code runs headless, which means from a script with no chat window.

## Pick a project

| Project | What it does |
|---|---|
| [Generate an architecture diagram](/use-cases/coding-agents/claude-code-repository-architecture-agent/) | Turns a repository into `arch.md`: a diagram and a short guide to how the code fits together. |
| [Review a pull request](/use-cases/coding-agents/pull-request-review-auto-fix-agent/) | Checks out a pull request, reviews it, posts the review on GitHub and saves any small fixes. |
| [Write 500 tests](/use-cases/coding-agents/test-writing-failure-reproduction-agent/) | Writes a large batch of tests, checks how many really exist, and fails below a set share. |
| [Find and fix security problems](/use-cases/coding-agents/claude-code-security-vulnerability-remediation-agent/) | Scans for known security problems, fixes what it can and opens a pull request. |
| [Make a code change and open a pull request](/use-cases/coding-agents/large-scale-refactor-migration-agent/) | Takes a change request in plain words, makes the change, tests it and opens a pull request. |

## What every project needs

- **An AerolVM server and the TypeScript SDK.** See [Quickstart](/quick-start/) and [SDK setup](/sdk-setup/).
- **Node.js 22 or newer.** The SDK streams live output over WebSocket, which Node.js has built in from version 22.
- **An Anthropic API key** in `ANTHROPIC_API_KEY`, so Claude Code can call the model.
- **A GitHub token** in `GITHUB_TOKEN`. It must be able to read the repository. Projects that push a branch or open a pull request also need write access.
- **Internet access from the sandbox.** The scripts download tools and talk to GitHub and the Anthropic API.

## How these projects work

1. **Create one sandbox per task.** Each repository, branch or pull request gets its own clean machine.
2. **Clone the repository inside the sandbox.** Then upload the prompt and any settings files.
3. **Run the agent.** Use `execStream` to watch a short job live. Use a session for a long job, because it keeps running if your connection drops.
4. **Download the results.** For example a report, a patch (a file listing every changed line) or a log.
5. **Delete the sandbox** when the job is done.

| SDK call | Why the projects use it |
|---|---|
| `create` | Start one sandbox per task, repository or branch. |
| `execStream` | See the agent's output live while it works. |
| `createSession`, `attachSession` | Keep a long job alive across dropped connections. |
| `uploadFile`, `downloadFile` | Move prompts, patches, logs and reports in and out. |
| `updateLifecycle` | Keep a sandbox alive longer while someone is still using it. |
