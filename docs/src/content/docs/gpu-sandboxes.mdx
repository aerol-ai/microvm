A GPU sandbox can use the graphics card (GPU) of the server it runs on. Use one for machine learning, CUDA or ROCm programs, or video work. The GPU is passed straight through, so programs in the sandbox see the real device.

GPU sandboxes are normal container sandboxes (`runtime: "docker"`, the default). gVisor, Firecracker, WebAssembly and V8 isolate sandboxes cannot use a GPU. If you ask for a GPU together with `runtime: "gvisor"`, the create call fails with an error.

## What the server needs

| GPU maker | `vendor` value | What the server needs |
|---|---|---|
| NVIDIA | `nvidia` | NVIDIA drivers (`nvidia-smi` works) and the NVIDIA Container Toolkit. The installer adds the toolkit with `--with-nvidia-gpu`. |
| AMD | `amd` | AMD ROCm, with the `amdgpu` kernel module loaded. The installer adds ROCm with `--with-amd-gpu`. x86_64 servers only. |
| Apple | `apple` | Docker Desktop on a Mac. It uses Docker Desktop's experimental Metal support. No installer flag. |

The server must also be told how many GPUs it has. Until it is, every GPU request fails with `host has no GPUs`. See [For server operators](#for-server-operators).

<Aside type="caution" title="Use a recent SDK">
SDK versions 0.6.4 and older drop the GPU request in TypeScript and Python, so the sandbox starts without a GPU, and the Rust SDK does not export the GPU types. Use a newer SDK release.
</Aside>

## Create a sandbox with one GPU

This asks for one NVIDIA GPU. When you leave out `count`, you get one GPU.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: "nvidia/cuda:12.2.0-base-ubuntu22.04",
      gpus: { vendor: "nvidia", count: 1 },
    });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create(
        image="nvidia/cuda:12.2.0-base-ubuntu22.04",
        gpus={"vendor": "nvidia", "count": 1},
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image: "nvidia/cuda:12.2.0-base-ubuntu22.04",
        GPUs: &sdktypes.GPURequest{
            Vendor: sdktypes.GPUVendorNVIDIA,
            Count:  1,
        },
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    use aerolvm_sdk::{CreateOptions, GPUOptions, GPUVendor};

    let sandbox = client.create(CreateOptions {
        image: "nvidia/cuda:12.2.0-base-ubuntu22.04".into(),
        gpus: Some(GPUOptions {
            vendor: GPUVendor::Nvidia,
            count: Some(1),
            device_ids: None,
        }),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("nvidia/cuda:12.2.0-base-ubuntu22.04")
            .setGpus(new GpuOptions().setVendor("nvidia").setCount(1))
    );
    ```
  </TabItem>
</Tabs>

## GPU options

| Option | What it does | Default |
|---|---|---|
| `vendor` | The GPU maker: `nvidia`, `amd` or `apple`. Required. | None |
| `count` | How many GPUs to give the sandbox. `-1` means every GPU on the server. Ignored for AMD. | `1` |
| `deviceIDs` | Pick exact GPUs by index (`"0"`, `"1"`) or UUID (`"GPU-abc123..."`). NVIDIA only. | The server picks |

The field is `deviceIDs` in TypeScript and Python, `DeviceIDs` in Go, `device_ids` in Rust and `setDeviceIds` in Java.

## If something goes wrong

| What you see | What it means |
|---|---|
| `host has no GPUs` | The server was not told it has GPUs. Ask the operator to set `SB_HOST_GPU_COUNT`. |
| `gpu reservation exceeded` | Other sandboxes already hold all the server's GPUs. Delete one, or ask for fewer. |
| `gpu vendor mismatch` | You asked for one maker's GPU, but the server has another. |
| `GPU access is not supported with the "gvisor" runtime` | Remove `runtime: "gvisor"`, or drop the GPU request. |
| `runtime "wasm" does not yet support GPUs` (or `firecracker`, `isolate`) | Firecracker, WebAssembly and V8 isolate sandboxes cannot use a GPU. |

## For server operators

Install the GPU software when you install the server. Add `--with-nvidia-gpu` or `--with-amd-gpu` to the install command (see [Install on a server](/getting-started/single-node-setup/)). On a cluster, set `with_nvidia_gpu = true` or `with_amd_gpu = true` on the worker in `terraform.tfvars` (see [Cluster setup](/cluster-setup/)).

- `--with-nvidia-gpu` installs the NVIDIA Container Toolkit and connects it to Docker. The NVIDIA drivers must already be installed.
- `--with-amd-gpu` installs ROCm from AMD's package repository. The `amdgpu` kernel module must already be loaded, so `/dev/kfd` exists.

Then tell AerolVM about the GPUs. The server counts every GPU it hands out and refuses requests beyond that number.

| Setting | What it does | Default |
|---|---|---|
| `SB_HOST_GPU_COUNT` | How many GPUs this server can hand out. `0` means none, so every GPU request fails. | `0` |
| `SB_HOST_GPU_VENDOR` | The GPU maker on this server (`nvidia`, `amd` or `apple`). Requests for another maker fail. | Empty (any maker) |

In a cluster, AerolVM uses these values to send GPU sandboxes only to servers that have a matching GPU.

<Aside type="caution">
GPU passthrough is built into the Docker engine only. AerolVM can also run containers through containerd, another container engine (`SB_CONTAINER_ENGINE=containerd`), but that engine does not attach GPUs to the sandbox. Run GPU servers with the Docker engine, which is the installer's default.
</Aside>
