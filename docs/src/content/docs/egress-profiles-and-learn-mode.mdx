import { Tabs, TabItem } from '@astrojs/starlight/components';

When many sandboxes need the same outbound access, such as a package mirror,
a source host and an internal API, writing the list into every create gets
out of date fast. An **egress profile** is a named allow list you keep once.
Sandboxes reference it by name, and when you change it, every sandbox that
uses it picks up the change. Profiles use the same entries as
[Egress Domain Filtering](/egress-domain-filtering): hostnames, `*.` wildcards,
`host:port` and CIDRs.

---

## Create a profile and use it

<Tabs syncKey="lang">

    ```ts
      description: 'pip and git over ssh',

    const sandbox = await client.create({
      image: 'python:3.12',
      egressProfiles: ['python-deps'],

    ```

A sandbox's allowed destinations are its own `networkAllowOut` entries plus
those of every profile it references. A profile is a full replace: sending the
same body again changes nothing, so it is safe to retry.

- **Names** are lower-case letters, digits, `.`, `_` and `-`, up to 63
  characters, and belong to your account like sandbox names.
- **Limits.** A profile holds up to 512 hostname entries, and a sandbox
  references up to 16 profiles. A sandbox's own entries and all its profiles
  together hold at most 1024 hostname entries, counted per list.
- **Profiles and block-all don't mix.** `networkBlockAll` with
  `egressProfiles` is refused.
- **Narrower than a host.** To allow only some methods or paths on a host a
  profile allows, add [egress rules](/egress-rules-and-inspection) to the
  sandbox. If a profile change later drops that host, its rules stop
  mattering: the host is refused anyway.

## Change a profile

Put the profile again with its new entries. Each change raises its
`generation`, and each sandbox reports the generation it has live in
`egressProfilesApplied`, so you can tell when a change has reached it.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const profile = await client.putEgressProfile('python-deps', {
      allowOut: ['pypi.org', '*.pythonhosted.org'],
    })
    const current = await client.get(sandbox.id)
    console.log(profile.generation, current.egressProfilesApplied)
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    profile = client.put_egress_profile('python-deps', {
        'allowOut': ['pypi.org', '*.pythonhosted.org'],
    })
    current = client.get(sandbox.id)
    print(profile['generation'], getattr(current, 'egressProfilesApplied', None))
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    profile, err := client.PutEgressProfile(ctx, "python-deps", sdktypes.EgressProfileOptions{
        AllowOut: []string{"pypi.org", "*.pythonhosted.org"},
    })
    if err != nil {
        return err
    }
    current, err := client.Get(ctx, sandbox.ID)
    if err != nil {
        return err
    }
    fmt.Println(profile.Generation, current.EgressProfilesApplied)
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let profile = client.put_egress_profile("python-deps", EgressProfileOptions {
        allow_out: vec!["pypi.org".to_string(), "*.pythonhosted.org".to_string()],
        ..Default::default()
    })?;
    let current = client.get(&sandbox.data.id)?;
    println!("{} {:?}", profile.generation, current.data.egress_profiles_applied);
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    EgressProfile profile = client.putEgressProfile("python-deps", new EgressProfileOptions()
        .setAllowOut(List.of("pypi.org", "*.pythonhosted.org")));
    Sandbox current = client.get(sandbox.id);
    System.out.println(profile.generation + " " + current.egressProfilesApplied);
    ```
  </TabItem>
</Tabs>

- **When it applies.** The node you sent the change to applies it to its
  sandboxes at once. In a cluster, every other node applies it to its own
  sandboxes within about 30 seconds. Connections the narrowed profile no
  longer allows are closed.
- **Refused changes.** A change that would push some sandbox that uses the
  profile past the 1024-entry limit is refused with `409`
  (`egress_profile_cap_exceeded`), naming the sandboxes. Nothing changes.
- **When a sandbox can't take it.** If a change can't be applied to one
  sandbox, that sandbox is shut (`egressStatus: "held"`) rather than left on
  the old list, and the change is retried every 10 seconds.

To change which profiles a running sandbox uses, call
[`setNetworkPolicy`](/egress-domain-filtering#change-the-policy-of-a-running-sandbox)
with `egressProfiles`.

## List and delete

`listEgressProfiles` returns your profiles a page at a time, by name; pass
`nextCursor` back as `cursor` for the next page. `deleteEgressProfile` refuses
with `409` (`egress_profile_in_use`) while any sandbox still references the
profile; deleting one that is already gone succeeds.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const page = await client.listEgressProfiles({ limit: 50 })
    for (const p of page.profiles) console.log(p.name, p.generation)
    await client.deleteEgressProfile('python-deps')
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    page = client.list_egress_profiles({'limit': 50})
    ```

  </TabItem>

## Built-in profiles

AerolVM ships allow lists for common package registries and source hosts.
Reference one as `builtin:<name>` anywhere you would use your own profile, on
its own or next to yours.

| Name | Covers |
|---|---|
| `builtin:pypi` | pip: `pypi.org` and `files.pythonhosted.org` |
| `builtin:npm` | npm and Yarn registries |
| `builtin:github` | `github.com`, its API, raw files, release downloads, `git` over SSH and `ghcr.io` |
| `builtin:huggingface` | `huggingface.co` and its download hosts |
| `builtin:golang-proxy` | the Go module proxy and checksum database |
| `builtin:crates` | `crates.io` and its download host |
| `builtin:apt-ubuntu` | the Ubuntu archive and security mirrors |
| `builtin:docker-hub` | Docker Hub's registry, token service and blob download hosts (Cloudflare, R2, and Docker's S3 bucket in `us-east-1`), for tools like `crane`. On AWS, Docker Hub serves blobs from its bucket in the client's region; outside `us-east-1`, add that bucket's host inline |

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'python:3.12',
      egressProfiles: ['builtin:pypi', 'builtin:github'],
    })
    console.log(sandbox.egressProfiles) // ['builtin:pypi@20261006', 'builtin:github@20261006']

    const pypi = await client.getEgressProfile('builtin:pypi')
    console.log(pypi.allowOut)
    ```
  </TabItem>
  <TabItem label="Python">
    ```python

        'image': 'python:3.12',
        'egressProfiles': ['builtin:pypi', 'builtin:github'],

    print(pypi['allowOut'])
    ```
  </TabItem>
  <TabItem label="Go">

  </TabItem>
  <TabItem label="Rust">

  </TabItem>
  <TabItem label="Java">
    ```java

        new CreateOptions()
            .setImage("python:3.12")
            .setEgressProfiles(List.of("builtin:pypi", "builtin:github"))
    );

    EgressProfile pypi = client.getEgressProfile("builtin:pypi");
    System.out.println(pypi.allowOut);
    ```
  </TabItem>
</Tabs>

- **Pinned at create.** `builtin:pypi` is stored as
  `builtin:pypi@<YYYYMMDD>`, the date of the list the node had when the
  sandbox was created. Upgrading AerolVM never changes what a running sandbox
  can reach. To move a sandbox to the newest list, call `setNetworkPolicy` with
  the bare name again. You can also ask for a dated version yourself.
- **Read-only.** You can read a built-in with `getEgressProfile` (the bare name
  gives the newest version), but not change or delete it. A built-in counts
  toward the 16-profile and 1024-entry limits like any other profile.
- **During an upgrade.** If a sandbox pinned to a list newer than a node has
  moves to that node, for example after a failover in the middle of a rolling
  upgrade, it runs with all outbound traffic blocked and
  `egressStatus: "unavailable"` until it is on a node that has that version.
  A new create asking for such a version on an older node gets `503`; retry it.
- **Missing a host?** The lists are maintained by hand. If a tool needs a host
  a list lacks, add the host to `networkAllowOut` next to the built-in.
- **Switched off.** Your operator can turn built-ins off. Then a create or
  policy change that names one gets `400` "built-in profiles disabled on this
  deployment", and sandboxes that already use one keep it.

## Org profiles

On a private network, your operator can publish allow lists for everyone on
the deployment, such as the bank's package mirrors, as `org:<name>` profiles.
Every account can read them and reference them like its own; only the
operator can change them.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const mirrors = await client.getEgressProfile('org:mirrors')
    console.log(mirrors.allowOut, mirrors.description)

    const sandbox = await client.create({
      image: 'python:3.12',
      egressProfiles: ['org:mirrors', 'python-deps'],
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    mirrors = client.get_egress_profile('org:mirrors')
    print(mirrors['allowOut'], mirrors.get('description'))

    sandbox = client.create({
        'image': 'python:3.12',
        'egressProfiles': ['org:mirrors', 'python-deps'],
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go

    if err != nil {
        return err
    }
    fmt.Println(mirrors.AllowOut, mirrors.Description)

    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:          "python:3.12",
        EgressProfiles: []string{"org:mirrors", "python-deps"},
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust

    println!("{:?} {}", mirrors.allow_out, mirrors.description);

    let sandbox = client.create(CreateOptions {
        image: "python:3.12".to_string(),
        egress_profiles: Some(vec!["org:mirrors".to_string(), "python-deps".to_string()]),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java

    System.out.println(mirrors.allowOut + " " + mirrors.description);

    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("python:3.12")
            .setEgressProfiles(List.of("org:mirrors", "python-deps"))
    );
    ```
  </TabItem>
</Tabs>

- **Not pinned.** Unlike built-ins, a sandbox follows its org profiles: when
  the operator edits one, every sandbox that uses it picks up the change
  within about 10 seconds, and `generation` changes.
- **The default policy.** When the operator's default policy names org
  profiles, a sandbox created without any egress settings references them, so
  it follows edits too.
- **When one goes away.** If the operator removes an org profile a sandbox
  uses, or grows it so the sandbox would pass the 1024-entry limit, that
  sandbox is shut (`egressStatus: "held"`) until the operator fixes it.
- **Unknown names** are refused with `400` at create and in
  `setNetworkPolicy`. Org profiles don't appear in `listEgressProfiles`; your
  operator publishes their names.

## Learn an allow list

Writing an allow list for a workload you didn't write is guesswork. **Learn
mode** gives a sandbox open egress for one trusted run and records every
destination it reaches. Read the recording and it comes with the allow list
that would have allowed that run, ready to lock the sandbox down.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({ image: 'python:3.12', networkEgressMode: 'learn' })
    await sandbox.exec('pip install requests')

    const learned = await sandbox.learned()
    console.log(learned.entries.map((e) => e.host))
    await sandbox.setNetworkPolicy({ networkAllowOut: learned.suggestedAllowOut })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({'image': 'python:3.12', 'networkEgressMode': 'learn'})
    sandbox.exec_command('pip install requests')

    learned = sandbox.learned()
    print([e['host'] for e in learned['entries']])
    sandbox.set_network_policy({'networkAllowOut': learned['suggestedAllowOut']})
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:             "python:3.12",
        NetworkEgressMode: sdktypes.NetworkEgressModeLearn,
    })
    if err != nil {
        return err
    }
    if _, err := sandbox.ExecCommand(ctx, "pip install requests"); err != nil {
        return err
    }
    learned, err := sandbox.Learned(ctx)
    if err != nil {
        return err
    }
    _, err = sandbox.SetNetworkPolicy(ctx, sdktypes.NetworkPolicyOptions{
        NetworkAllowOut: learned.SuggestedAllowOut,
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let mut sandbox = client.create(CreateOptions {
        image: "python:3.12".to_string(),
        network_egress_mode: Some("learn".to_string()),
        ..Default::default()
    })?;
    sandbox.exec(ExecRequest {
        command: "pip install requests".to_string(),
        ..Default::default()
    })?;

    let learned = sandbox.learned()?;
    sandbox.set_network_policy(NetworkPolicyOptions {
        network_allow_out: learned.suggested_allow_out,
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(
        new CreateOptions().setImage("python:3.12").setNetworkEgressMode("learn"));
    sandbox.exec("pip install requests");

    NetworkLearned learned = sandbox.learned();
    sandbox.setNetworkPolicy(new NetworkPolicyOptions().setNetworkAllowOut(learned.suggestedAllowOut));
    ```
  </TabItem>
</Tabs>

- **Trusted runs only.** A learn-mode sandbox can reach anything, so use it
  for code you trust and switch it to enforce before untrusted code runs.
  Every connection it makes is written to the
  [audit log](/egress-domain-filtering#see-what-was-refused) with reason
  `learn_mode`.
- **Rules.** Learn mode takes no allow or deny lists, no profiles and no
  block-all; it is never a default.
- **The suggestion.** Three or more names under one domain collapse to
  `*.domain` (never a public suffix), non-web ports stay as `host:port`, and
  addresses reached without a DNS name become single-address CIDRs. When the
  suggestion holds more than 64 hostnames it comes back as
  `suggestedProfile`, a body for `putEgressProfile`, instead of
  `suggestedAllowOut`.
- **Limits.** A recording holds up to 1024 destinations; past that,
  `truncated` is true and new destinations aren't recorded.
- **How long it lasts.** A recording stays readable after the sandbox
  switches to enforce, and goes when the sandbox is destroyed. It isn't
  replicated, so a sandbox recreated on another node after a failure starts
  a new one. A WASM sandbox's recording lives in its running worker and goes
  when it stops.

## Check a policy before you use it

`checkNetworkPolicy` answers whether a sandbox created with some egress fields
would reach a destination, using the same matcher the filter enforces. No
sandbox is created. The destination is a host, `host:port`, an IP or
`IP:port`; a bare host is checked on the web ports.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const check = await client.checkNetworkPolicy({
      networkAllowOut: ['*.github.com'],
      destination: 'api.github.com',
    })
    console.log(check.allowed, check.matchedRule) // true "*.github.com"
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    check = client.check_network_policy({
        'networkAllowOut': ['*.github.com'],
        'destination': 'api.github.com',
    })
    print(check['allowed'], check['matchedRule'])  # True "*.github.com"
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    check, err := client.CheckNetworkPolicy(ctx, sdktypes.NetworkPolicyCheckOptions{
        NetworkAllowOut: []string{"*.github.com"},
        Destination:     "api.github.com",
    })
    if err != nil {
        return err
    }
    fmt.Println(check.Allowed, check.MatchedRule) // true *.github.com
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let check = client.check_network_policy(NetworkPolicyCheckOptions {
        network_allow_out: vec!["*.github.com".to_string()],
        destination: "api.github.com".to_string(),
        ..Default::default()
    })?;
    println!("{} {}", check.allowed, check.matched_rule); // true *.github.com
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    NetworkPolicyCheckResult check = client.checkNetworkPolicy(new NetworkPolicyCheckOptions()
        .setNetworkAllowOut(List.of("*.github.com"))
        .setDestination("api.github.com"));
    System.out.println(check.allowed + " " + check.matchedRule); // true *.github.com
    ```
  </TabItem>
</Tabs>

The answer also gives `defaultVerdict`, what happens to a destination no entry
matches, and `outsideCeiling` when an entry falls outside the limits your
operator set, which is why such a create would be refused. The check doesn't
resolve DNS, so a deny CIDR that a hostname's address would hit is only
caught when the sandbox connects.

## Limitations

- **Learn mode and the E2B SDK.** `updateNetwork` keeps a sandbox in learn
  mode; setting lists on a learn-mode sandbox from the E2B SDK is refused with
  `409`. Switch it with `setNetworkPolicy`.
- **E2B SDK.** `updateNetwork` from the [E2B facade](/using-e2b-sdk) keeps a
  sandbox's profiles, since the E2B API has no way to name them.
