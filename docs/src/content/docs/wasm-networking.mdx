A [WASM sandbox](/wasm-sandbox/) has no network card of its own. The AerolVM server handles its network traffic for it. For incoming web requests, AerolVM's web proxy sends each request to a small relay on the server. The relay passes it to the listener your module serves on.

So the port number you pass to `exposePort` is a label for the public URL. It is not a TCP port your module opens inside the sandbox.

## Share a web server

Call `exposePort` to get a public URL. HTTP is the default, and the only kind WASM supports. The URL looks like `https://<sandbox-id>-<port>.<domain>`.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const exposure = await sandbox.exposePort(8080);
    console.log(exposure.url);
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    exposure = sandbox.expose_port(8080)
    print(exposure.url)
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    exposure, err := sandbox.ExposePort(ctx, 8080)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Println(exposure.PublicURL)
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let exposure = sandbox.expose_port(8080, ExposeOptions::http())?;
    if let ExposeResult::Http { url } = exposure {
        println!("{}", url);
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    ExposeResult exposure = sandbox.exposePort(8080);
    System.out.println(exposure.url);
    ```
  </TabItem>
</Tabs>

A new sandbox is private. Calling `exposePort` makes it public. It is safe to call again: a retry returns the same URL.

## Use your own domain

You can point your own hostname, such as `api.acme.com`, at a WASM sandbox. The port you pass picks what answers:

| Port | What answers |
|---|---|
| `0` | The toolbox, the helper the SDK talks to. This is the same as the sandbox's default `<sandbox-id>.<domain>` address. |
| An exposed HTTP port, such as `8080` | Your module's web server, the same as its `exposePort` URL. |

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    await sandbox.customDomains.add("api.acme.com", { port: 8080 });
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox.add_custom_domain("api.acme.com", port=8080)
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    _, err := sandbox.AddCustomDomain(ctx, "api.acme.com", microvm.WithTargetPort(8080))
    if err != nil {
        log.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    sandbox.add_custom_domain(
        "api.acme.com",
        Some(AddCustomDomainOptions::with_port(8080)),
    )?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    sandbox.addCustomDomain("api.acme.com", 8080);
    ```
  </TabItem>
</Tabs>

You can add the domain before you call `exposePort`. Once the port is exposed, the routes update by themselves. If the sandbox already exposes HTTP ports, the port you pass must be one of them, or `0`. The hostname's DNS record (its entry in the internet's address book) must point at your server first. See [Custom domains](/custom-domains/) for DNS and certificates.

## What your module must do

- **Serve incoming requests** on the TCP listener the server opens for the module before it starts (a pre-opened socket). Find it with the WASI socket functions (WASI is the standard system interface for WebAssembly programs). TinyGo and other real-world modules do this.
- **Make outgoing connections** through the server. Outbound TCP and UDP go through `aerol/vm/net`, a set of network functions the server gives the module. See [WASM architecture](/wasm-architecture/).
- **Do not assume the listener's number.** A file descriptor is the number a program uses for an open file or socket. When the module also has the `/work` folder open, the listener's number may be above 3. Find it with the WASI socket functions. Some test modules expect it at 3, but they are meant only for testing the engine.

## Limits

- **No TCP or TLS ports.** `exposePort` with `tcp` or `tls` (encrypted TCP) fails with `runtime not implemented` on WASM.
- **No WASI Preview 2.** Modules built for WASI Preview 2 (the Component Model) cannot take incoming connections on the default `wazero` engine.
- **Custom domains and TCP or TLS ports do not mix** on one sandbox. This is the same rule as for container sandboxes.
