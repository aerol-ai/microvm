[NVIDIA NeMo Gym](https://github.com/NVIDIA-NeMo/Gym) builds environments for training language models with reinforcement learning. Many of its agents (coding agents, terminal tasks) need a sandbox for every rollout. NeMo Gym gets those sandboxes from a *provider*, picked in its config.

The `aerolvm-nemo-gym` package adds a provider named `aerolvm`. With it, every NeMo Gym sandbox is an AerolVM sandbox.

## Install

NeMo Gym's provider system is newer than its latest PyPI release (0.4.0), so install NeMo Gym from GitHub. It needs Python 3.14.

```bash
pip install "nemo-gym @ git+https://github.com/NVIDIA-NeMo/Gym.git"
pip install "git+https://github.com/aerol-ai/microvm.git#subdirectory=integrations/nemo-gym"
```

Installing the package is enough: NeMo Gym finds the `aerolvm` provider by itself. Set the same two variables as for the [Python SDK](/sdk-setup/):

```bash
export SB_API_URL=https://sandbox.example.com
export SB_PAT_TOKEN=your-token
```

## Point NeMo Gym at AerolVM

Every NeMo Gym provider config is a block named `sandbox`. Save this as `aerolvm.yaml` (the package also ships it as `integrations/nemo-gym/configs/aerolvm.yaml`):

```yaml
sandbox:
  default_metadata:
    sandbox-api: aerolvm
  aerolvm:
    api_url: ${oc.env:SB_API_URL}
    api_token: ${oc.env:SB_PAT_TOKEN}
    default_image: python:3.12-slim
    exec_timeout_s: 180
    probe_deadline_s: 60
    create_options: {}
```

Then pass it where you would pass another provider's config:

```bash
gym env start \
    --config responses_api_agents/mini_swe_agent_2/configs/mini_swe_agent_2.yaml \
    --config aerolvm.yaml \
    --config responses_api_models/vllm_model/configs/vllm_model.yaml
```

The agent's config does not change.

## What it does with the sandbox

| NeMo Gym asks for | AerolVM does |
| --- | --- |
| A new sandbox | Creates one from the spec's image (or `default_image`), with its environment variables, CPU, memory and disk. Its metadata becomes [tags](/sandbox-tags/), plus `integration=nemo-gym`. The call returns once the sandbox runs a command. If NeMo Gym cancels the call while the sandbox is being made, the sandbox is deleted as soon as it exists. Each create also gets its own `aerolvm-create-op` tag. If a create fails with no clear answer (a lost connection, say), the provider looks for a sandbox with that tag and deletes it. |
| The spec's `ttl_s` | Sets the sandbox to delete itself at that age, so a crashed training run does not leave sandboxes behind. |
| The spec's `workdir` | Makes the folder, and runs commands there by default. |
| A command | Runs it with the folder, variables and time limit NeMo Gym gives. A command that runs out of time returns exit code 124. |
| Upload and download a file | Uses the SDK's file upload and download. |
| Status | Reads the sandbox's status. |
| Close | Destroys the sandbox. |

`create_options` takes any other create fields for every sandbox, for example `runtime: firecracker`, `networkBlockAll: true`, or a [lifecycle](/lifecycle/).

## Or use NeMo Gym's Daytona provider

NeMo Gym also ships a provider for Daytona, and AerolVM [serves Daytona's API](/using-daytona-sdk/). That works too. We tested every Daytona call the provider makes (create, get, status, commands with a folder, variables and a time limit, file upload and download, and delete) with the Daytona Python SDK 0.179.0 and 0.230.0.

Keep NeMo Gym's own `daytona.yaml`, and point the Daytona SDK at `/daytona` on your server:

```bash
export DAYTONA_API_KEY=$SB_PAT_TOKEN
export DAYTONA_API_URL=$SB_API_URL/daytona

gym env start \
    --config responses_api_agents/mini_swe_agent_2/configs/mini_swe_agent_2.yaml \
    --config nemo_gym/sandbox/providers/daytona/configs/daytona.yaml \
    --config responses_api_models/vllm_model/configs/vllm_model.yaml
```

Pick the `aerolvm` provider when you want AerolVM's own features: tags on every sandbox, sandboxes that delete themselves at `ttl_s`, and `create_options` such as `runtime: firecracker`. Pick the Daytona provider when you already run NeMo Gym against Daytona and want to change only the address.

## Limits

- Commands run as the sandbox's user. Asking NeMo Gym for another user per command fails with a clear error; set `create_options.osUser` to choose the sandbox's user instead.
- GPU requests and sidecar containers are refused, so a spec that needs them fails before a sandbox is made.
- Each upload holds the whole file in memory.
