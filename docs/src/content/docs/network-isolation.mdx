A new sandbox can reach the whole internet. That is handy, but code you do not trust could use it to send your data somewhere else. On this page you turn outbound traffic (traffic that leaves the sandbox) off, or limit it to lists of IP addresses.

The page also covers the other direction: who can reach the sandbox from outside. A new sandbox has no public web address until you ask for one.

## Which networking page do you need?

| You want to | Read |
|---|---|
| Turn the internet off, or allow or block ranges of IP addresses | This page |
| Allow only some websites by name, such as `pypi.org` | [Allow only some websites](/egress-domain-filtering/) |
| Save an allow list once and reuse it, or build one by watching a trusted run | [Reusable allow lists](/egress-profiles-and-learn-mode/) |
| Allow only some requests to a website, or keep an API key out of the sandbox | [Rules and inspection](/egress-rules-and-inspection/) |
| Count or cap the bytes a sandbox sends and receives | [Usage and limits](/network-usage/) |

## Turn off the internet

Set `networkBlockAll` to `true` when you create the sandbox.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'ubuntu:22.04',
      networkBlockAll: true,
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'ubuntu:22.04',
        'networkBlockAll': True,
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:           "ubuntu:22.04",
        NetworkBlockAll: true,
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".to_string(),
        network_block_all: Some(true),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("ubuntu:22.04")
            .setNetworkBlockAll(true)
    );
    ```
  </TabItem>
</Tabs>

Now every outbound connection fails at once. That includes web requests, database connections and DNS lookups (DNS is the system that turns a name like `example.com` into an IP address).

Inbound traffic still works. If you publish a port, people can still reach the app behind it. See [Who can reach the sandbox from outside](#who-can-reach-the-sandbox-from-outside).

### Check that it is blocked

Run a command that needs the internet. It should fail with a non-zero exit code.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const result = await sandbox.exec({
      command: 'curl -I https://google.com',
    })
    console.log(`Exit code: ${result.exitCode}`) // not 0: the request was blocked
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    result = sandbox.exec({
        'command': 'curl -I https://google.com'
    })
    print(f"Exit code: {result['exitCode']}")
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    result, err := sandbox.Exec(ctx, sdktypes.ExecRequest{
        Command: "curl -I https://google.com",
    })
    if err != nil {
        return err
    }
    fmt.Printf("Exit code: %d\n", result.ExitCode)
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let result = sandbox.exec(ExecRequest {
        command: "curl -I https://google.com".to_string(),
        ..Default::default()
    })?;
    println!("Exit code: {}", result.exit_code);
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.model.ExecRequest;
    import ai.aerol.microvm.model.ExecResult;

    ExecResult result = sandbox.exec(
        new ExecRequest().setCommand("curl -I https://google.com")
    );
    System.out.println("Exit code: " + result.exitCode);
    ```
  </TabItem>
</Tabs>

<Aside type="caution">
The server's firewall does the blocking, and it only runs on Linux. On the macOS install from the [Quickstart](/quick-start/), a sandbox with these settings still starts, but nothing is blocked. Test network rules on a Linux server.
</Aside>

## Allow or block lists of IP addresses

Blocking everything is often too strict. An agent may need one API while everything else stays off. For that, give the sandbox a list of address ranges.

An address range is written as an IP address, a slash and a number. `8.8.8.8/32` is one address. `10.0.0.0/8` is every address that starts with `10.`. Networking tools call this form a CIDR.

| Option | What it does |
|---|---|
| `networkAllowOut` | The sandbox can reach only these ranges. All other outbound traffic is dropped. |
| `networkDenyOut` | The sandbox can reach everything except these ranges. |
| `networkBlockAll` | The sandbox can reach nothing. |

This sandbox can reach `1.1.1.0/24` and `8.8.8.8`, and nothing else:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    // Allow only 1.1.1.0/24 and 8.8.8.8; block everything else.
    const sandbox = await client.create({
      image: 'ubuntu:22.04',
      networkAllowOut: ['1.1.1.0/24', '8.8.8.8/32'],
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'ubuntu:22.04',
        'networkAllowOut': ['1.1.1.0/24', '8.8.8.8/32'],
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:           "ubuntu:22.04",
        NetworkAllowOut: []string{"1.1.1.0/24", "8.8.8.8/32"},
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".to_string(),
        network_allow_out: Some(vec!["1.1.1.0/24".to_string(), "8.8.8.8/32".to_string()]),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import java.util.List;

    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("ubuntu:22.04")
            .setNetworkAllowOut(List.of("1.1.1.0/24", "8.8.8.8/32"))
    );
    ```
  </TabItem>
</Tabs>

To do the opposite, block a few ranges and allow the rest, pass the list to `networkDenyOut`:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'ubuntu:22.04',
      networkDenyOut: ['10.0.0.0/8'], // block the internal range, allow the rest
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'ubuntu:22.04',
        'networkDenyOut': ['10.0.0.0/8'],
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:          "ubuntu:22.04",
        NetworkDenyOut: []string{"10.0.0.0/8"},
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".to_string(),
        network_deny_out: Some(vec!["10.0.0.0/8".to_string()]),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import java.util.List;

    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("ubuntu:22.04")
            .setNetworkDenyOut(List.of("10.0.0.0/8"))
    );
    ```
  </TabItem>
</Tabs>

The lists are saved with the sandbox. They come back after a stop and start, and after the server restarts, the same as `networkBlockAll`.

### Use both lists together

You can set both lists. The server decides each connection in this order:

1. A destination in `networkAllowOut` is allowed.
2. Otherwise, a destination in `networkDenyOut` is dropped.
3. Anything else is allowed.

So to make the allow list the only way out, also set `networkDenyOut` to `['0.0.0.0/0']` (every IPv4 address). That deny list on its own blocks everything, the same as `networkBlockAll`.

The deny list takes address ranges only. The allow list also takes website names, such as `pypi.org`. See [Allow only some websites](/egress-domain-filtering/).

To change the lists while the sandbox runs, use `setNetworkPolicy`. See [Change the policy of a running sandbox](/egress-domain-filtering/#change-the-policy-of-a-running-sandbox).

## Who can reach the sandbox from outside

The settings above control traffic going out. Inbound traffic (traffic coming in from the internet) is a separate choice, and the default is private.

A private sandbox has no public `<sandbox-id>.<domain>` address, and its public URL is empty. You can still run commands, copy files and connect over SSH. Those go through the server directly, not through the public address.

There are two ways to make a sandbox public:

1. **Call `exposePort`.** Asking for a public port is your consent. The first call on a private sandbox makes it public, sets up its `<sandbox-id>.<domain>` address, and then publishes the port. See [Share a web app](/preview/).
2. **Set `allowPublicTraffic: true` when you create it.** Use this if you want the sandbox's address to work from the start, before you publish any port.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'ubuntu:22.04',
      allowPublicTraffic: true,
    })
    // sandbox.publicURL works from the start, before any exposePort call.
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'ubuntu:22.04',
        'allowPublicTraffic': True,
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    publicOn := true
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:              "ubuntu:22.04",
        AllowPublicTraffic: &publicOn,
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "ubuntu:22.04".to_string(),
        allow_public_traffic: Some(true),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("ubuntu:22.04")
            .setAllowPublicTraffic(true)
    );
    ```
  </TabItem>
</Tabs>

Good to know:

- **Public is for good.** Once you publish a port, the sandbox stays public, even if you later unpublish every port.
- **`false` is the same as leaving it out.** The sandbox starts private, and a later `exposePort` call still makes it public.
- **A custom domain does not make a sandbox public.** Adding one to a private sandbox returns an error. Publish a port first, or create the sandbox with `allowPublicTraffic: true`.
- **Private sandboxes start a little faster.** The server skips setting up a public address while it creates them.
- **Daytona and E2B apps are public by default.** The [Daytona SDK](/using-daytona-sdk/) `public` field sets this flag, and leaving it out means `true`, as on Daytona. The [E2B SDK](/using-e2b-sdk/) always turns it on, because E2B sandboxes are public by design.

### Blocking outbound traffic does not close published ports

`networkBlockAll` and the lists only affect traffic going out. A port you publish still answers requests from the internet:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    // Expose port 80 to the public internet
    const exposure = await sandbox.exposePort(80)
    console.log(`Access the isolated sandbox at: ${exposure.url}`)
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    exposure = sandbox.expose_port(80)
    print(f"Access the isolated sandbox at: {exposure.url}")
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    exposure, err := sandbox.ExposePort(ctx, 80)
    if err != nil {
        return err
    }
    fmt.Printf("Access the isolated sandbox at: %s\n", exposure.PublicURL)
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    use aerolvm_sdk::ExposeOptions;

    let exposure = sandbox.expose_port(80, ExposeOptions::http())?;
    if let aerolvm_sdk::ExposeResult::Http { url } = exposure {
        println!("Access the isolated sandbox at: {}", url);
    }
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    import ai.aerol.microvm.model.ExposeResult;

    ExposeResult exposure = sandbox.exposePort(80);
    System.out.println("Access the isolated sandbox at: " + exposure.url);
    ```
  </TabItem>
</Tabs>

The app inside answers on its public URL, even though the sandbox cannot start a connection to the internet itself.

## Make your app accept the public address

Every web request carries a `Host` header with the address the visitor used. For a published port, that is the sandbox's own address, such as `<sandbox-id>-3000.<your-domain>`. Many dev servers and frameworks refuse requests for an address they do not know:

- Vite (`server.allowedHosts`): "Blocked request. This host is not allowed."
- webpack-dev-server (`allowedHosts`)
- Django (`ALLOWED_HOSTS`) and Rails host authorization

Set `maskRequestHost` to a value your app accepts, usually `localhost`. The public URL stays the same. Only the `Host` header your app sees changes. Leave it unset to pass the header through as it is.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.create({
      image: 'node:22',
      maskRequestHost: 'localhost',
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.create({
        'image': 'node:22',
        'maskRequestHost': 'localhost',
    })
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Create(ctx, sdktypes.CreateSandboxOptions{
        Image:           "node:22",
        MaskRequestHost: "localhost",
    })
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.create(CreateOptions {
        image: "node:22".to_string(),
        mask_request_host: Some("localhost".to_string()),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.create(
        new CreateOptions()
            .setImage("node:22")

    ```
  </TabItem>
</Tabs>

This works on HTTP ports only. It also applies when a request wakes a paused sandbox. Raw [TCP and TLS ports](/tcp-ports/) carry no `Host` header, so the setting does nothing there.

## Cap traffic instead of blocking it

You do not have to choose between all or nothing. You can let a sandbox use the internet up to a number of bytes in each direction. You set the caps at create, read live counters, and raise or remove a cap while the sandbox runs. See [Usage and limits](/network-usage/).

## Limits

- **IPv4 only.** These rules and the byte caps cover IPv4 traffic. If the sandbox has IPv6 routing, its IPv6 connections are not blocked.
- **Linux servers only.** The rules are enforced by the server's firewall, which runs only on Linux. On macOS, nothing is blocked.
- **Website names need the filter service.** `networkAllowOut` also takes names, `*.` wildcards and `host:port` entries. See [Allow only some websites](/egress-domain-filtering/). For container sandboxes, a filter service on each server checks them. A server that cannot run it refuses a create that lists names (HTTP `501`). Lists of address ranges still work there.

## For server operators

| Setting | What it does | Default |
|---|---|---|
| `SB_ENABLE_NETWORK_RULES` | Turns on the per-sandbox firewall rules behind `networkBlockAll`, the address lists and the byte caps. Linux only. When off, Docker sandboxes start without the rules, and Firecracker sandboxes refuse these options. | `true` |
| `SB_NETRULES_BACKEND` | How the rules are written: `netlink` (nftables) or `exec` (the `iptables` tool). | `netlink` |
