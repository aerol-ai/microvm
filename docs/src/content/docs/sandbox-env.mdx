Environment variables set at create time are secrets. `get` and `list` **omit `env` by default**. Pass an explicit opt-in to load them; those reads are audited on the daemon.

Create, get, and list responses are redacted unless the read API explicitly
opts in to env materialization.

At rest, env values exist only as an authenticated encrypted blob in
`sandbox_env`, bound to the sandbox ID **and its lifecycle incarnation**.
Copying ciphertext to another sandbox, or to a replacement that reuses its ID,
does not make it decryptable there. Missing keys or invalid ciphertext fail
closed. A sandbox created without environment variables has no env row.

Startup transactionally migrates legacy plaintext columns and upgrades older
unbound encrypted env rows using the existing encryption key. The binding
upgrade is recorded in the schema; normal reads and subsequent restarts never
fall back to unbound decryption. Back up the database **and its matching key**
before upgrading, and retain them together for rollback to an older binary.
Do not run an older binary against an upgraded database.

## Migrating existing clients

Hiding env is an intentional breaking response-contract change, including
single-node and local deployments. An absent `env` in a default response does
**not** mean that the sandbox lost its environment. There is no server flag
that restores plaintext disclosure to old clients.

1. Identify code that reads `sandbox.env` after get/list (including code that
   copies those values into a new create request). Do not interpret a redacted
   response as an empty environment to propagate elsewhere.
2. Upgrade the SDK to a release with the opt-in methods below, then request env
   only where the application actually needs secret values. Routine inventory,
   status polling, and dashboards should continue using the redacted defaults.
3. Test both the explicit read and the redacted default in a staging deployment
   before upgrading production. Confirm the explicit read produces an audit
   event and that the application does not log the returned secrets.

The next two sections show the replacement calls for all five SDKs. Clients
that cannot yet be upgraded need an application migration before this server
upgrade; they are not silently made compatible by the database migration.

## Get a sandbox with env

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.get(id, { includeEnv: true })
    console.log(sandbox.env?.API_KEY)
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.get(sandbox_id, include_env=True)
    print(sandbox.get('env', {}).get('API_KEY'))
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Get(ctx, id, microvm.WithGetIncludeEnv())
    if err != nil {
        return err
    }
    fmt.Println(sandbox.Env["API_KEY"])
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.get_with_options(&id, true)?;
    println!("{:?}", sandbox.data.env);
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.get(id, true);
    System.out.println(sandbox.env.get("API_KEY"));
    ```
  </TabItem>
</Tabs>

## List sandboxes with env

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandboxes = await client.list({
      tags: { tenant: 'acme' },
      includeEnv: true,
    })
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandboxes = client.list(
        tags={'tenant': 'acme'},
        include_env=True,
    )
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandboxes, err := client.List(ctx,
        microvm.WithTags(map[string]string{"tenant": "acme"}),
        microvm.WithIncludeEnv(),
    )
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let mut tags = std::collections::HashMap::new();
    tags.insert("tenant".into(), "acme".into());
    let sandboxes = client.list_with_options(&tags, true)?;
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    java.util.Map<String, String> tags = new java.util.HashMap<>();
    tags.put("tenant", "acme");
    java.util.List<Sandbox> sandboxes = client.list(tags, true);
    ```
  </TabItem>
</Tabs>

## Default get/list (no env)

Omit the opt-in flag — responses do not include `env`.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">
    ```ts
    const sandbox = await client.get(id)
    // sandbox.env is undefined / empty
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    sandbox = client.get(sandbox_id)
    # sandbox has no env (or empty)
    ```
  </TabItem>
  <TabItem label="Go">
    ```go
    sandbox, err := client.Get(ctx, id)
    // sandbox.Env is nil / empty
    ```
  </TabItem>
  <TabItem label="Rust">
    ```rust
    let sandbox = client.get(&id)?;
    // sandbox.data.env is None / empty
    ```
  </TabItem>
  <TabItem label="Java">
    ```java
    Sandbox sandbox = client.get(id);
    // sandbox.env is null / empty
    ```
  </TabItem>
</Tabs>
