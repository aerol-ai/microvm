This page explains the words you see in cluster logs and docs. It also lists the settings on each node. Use it to read logs, fix problems, or change settings that Terraform sets for you.

## Words you will see

| Word | What it means |
|---|---|
| Cluster | A group of AerolVM servers that work together as one system. |
| Node | One server in the cluster. |
| Seed | The first node. It starts the cluster, and every other node joins it. |
| Role | The jobs a node does: `server`, `worker`, `ingress`, or all three (`mixed`). |
| Placement map | The shared record of which sandbox lives on which node. |
| Owner | The node a sandbox runs on. Requests for that sandbox are forwarded to it. |
| Raft | The method server nodes use to agree on every change to the placement map. |
| Voter | A server node that votes on changes in Raft. |
| Leader | The one voter that makes changes at a time. If it fails, the voters pick a new one. |
| Quorum | A majority of voters. Changes go through only while a quorum is online. |
| Gossip | A light protocol (it uses one called SWIM) that every node uses to find the others and share its free space. |
| Ingress | Traffic coming in from the internet, and the nodes that receive it. |
| Drain | Mark a node so it gets no new sandboxes. Sandboxes already on it keep running. |
| Orphaned | A sandbox whose owner died. Normal sandboxes then return `410 Gone`. |
| PAT token | The shared access token (`SB_PAT_TOKEN`) that operators, SDKs and nodes use. |

## Node roles

Each node's role decides what it does.

| Role | Votes in Raft | Runs sandboxes | Takes public traffic |
|---|---|---|---|
| `mixed` | Yes | Yes | Yes |
| `server` | Yes | No | No |
| `worker` | No | Yes | No |
| `ingress` | No | No | Yes |
| `server,worker` | Yes | Yes | No |
| `server,ingress` | Yes | No | Yes |
| `worker,ingress` | No | Yes | Yes |

**Raft** keeps every server node in agreement on which sandbox lives where. Nodes with `server` in their role (or `mixed`) vote. A majority of voters must be online to make changes. Worker and ingress nodes do not join Raft at all. They can run sandboxes and forward traffic without changing that majority.

**Gossip** is how every node, whatever its role, finds the others. Nodes also use it to share changes when a node joins or leaves.

For when to use each role, see [Ingress nodes](/cluster-ingress/).

## How many voting nodes you need

| Voting nodes | Can lose | Notes |
|---|---|---|
| 1 | 0 | Testing only. |
| 2 | 0 | Avoid. It has the same safety as 1 voter, but both must agree. |
| 3 | 1 | The minimum for production. |
| 5 | 2 | Good when nodes are spread across availability zones (separate data centers). |
| 7 | 3 | Little extra gain, and each change takes more work to copy. |

Always use an **odd number** of voting nodes. An even number raises the majority you need without letting you lose more nodes.

`SB_CLUSTER_MAX_AUTO_VOTERS` caps how many server nodes become voters on their own. The default cap is `5`. Server nodes past the cap join as **non-voters**: they still get every change, but they do not count toward the majority.

## Cluster settings

Terraform writes these settings to `/etc/sandboxd/cluster.env` on each node when you run `scripts/terraform.sh apply`. You do not need to set them yourself. They help when you read logs or fix problems.

### Node identity

| Variable | What it does | Default |
|---|---|---|
| `SB_ENABLE_CLUSTER` | Set to `true` to turn on cluster mode. | `false` |
| `SB_NODE_ID` | A fixed name for this node, such as `node1`. Never change it after the node joins. A new ID leaves a "ghost" entry for the old one in the cluster's records. | Required |
| `SB_NODE_ROLE` | This node's role. See [Node roles](#node-roles). | `mixed` |
| `SB_CLUSTER_BOOTSTRAP` | `true` only on the seed, `false` on all other nodes. Only a role with `server` (or `mixed`) may be the seed. | `false` |
| `SB_CLUSTER_MAX_AUTO_VOTERS` | The most server nodes that become voters on their own. Extra server nodes join as non-voters. `0` means no cap. | `5` |

### Networking

| Variable | What it does | Default |
|---|---|---|
| `SB_API_ADVERTISE_URL` | The address other nodes use to forward API requests to this node, for example `http://10.0.0.5:21212`. | `http://<hostname>:21212` |
| `SB_DATA_PLANE_ADVERTISE_HOST` | The host other nodes use to send sandbox traffic here. Set it when that differs from the API address. | The host in `SB_API_ADVERTISE_URL` |
| `SB_BOOTSTRAP_PEERS` | Gossip addresses to contact when joining, separated by commas. Required on every node except the seed. | Empty |
| `SB_INGRESS_ADVERTISE_HOST` | The public host name used in sandbox URLs. See [Ingress nodes](/cluster-ingress/). | Empty |

### Raft settings

Raft keeps its records on disk, so they survive restarts.

| Variable | What it does | Default |
|---|---|---|
| `SB_RAFT_BIND_ADDR` | The address Raft listens on. | `0.0.0.0:7000` |
| `SB_RAFT_ADVERTISE_ADDR` | The address other nodes use to reach Raft here. It must be a real address they can reach, not `0.0.0.0`. | Required (Terraform and the setup scripts set it) |
| `SB_RAFT_DATA_DIR` | Where Raft stores its log and snapshots (saved copies of its state). | `/var/lib/sandboxd/raft` |

### Gossip settings

| Variable | What it does | Default |
|---|---|---|
| `SB_GOSSIP_BIND_ADDR` | The address gossip listens on. | `0.0.0.0:7001` |
| `SB_GOSSIP_ADVERTISE_ADDR` | The address other nodes use to reach gossip here. It must be a real address they can reach, not `0.0.0.0`. | Required (Terraform and the setup scripts set it) |
| `SB_GOSSIP_SECRET_KEY` | A shared key, base64-encoded, of 16, 24 or 32 bytes. Every node must have the same one. It signs gossip messages so strange machines cannot join. Required. | Empty |
| `SB_CLUSTER_INSECURE_GOSSIP` | Skip the gossip key. Only safe on a fully closed network that untrusted machines cannot reach. Not allowed in enterprise mode. | `false` |

### Security settings

| Variable | What it does | Default |
|---|---|---|
| `SB_CLUSTER_TLS_DIR` | The folder with the cluster's certificate authority and this node's certificate and key (`ca.crt`, `node.crt`, `node.key`). Traffic between nodes then uses mutual TLS (both sides show a certificate). A PAT token alone cannot fake requests between nodes. Required in cluster mode. | Empty |
| `SB_CLUSTER_INTERNAL_LISTEN` | Where the private node-to-node HTTPS listener binds. | `0.0.0.0:7002` |
| `SB_CLUSTER_INTERNAL_ADVERTISE` | The HTTPS address other nodes use for that listener, for example `https://10.0.0.5:7002`. | Worked out from the node's main IP |
| `SB_CREDENTIAL_ENCRYPTION_KEY` | The shared key for the local secrets provider. Required in cluster mode, unless the key file exists. It is not enough for failover on its own. See [Secrets providers](/cluster-secrets/). | Empty |
| `SB_CREDENTIAL_ENCRYPTION_KEY_PATH` | A file to read that key from. | `/var/lib/sandboxd/credential_encryption.key` |
| `SB_CLUSTER_INSECURE_CREDENTIALS` | Skip the key requirement. Only for short-lived tests that use no sealed passwords. Not allowed in enterprise mode. | `false` |
| `SB_SECRET_PROVIDER` | `local`, `awskms` or `vault` (not built yet). See [Secrets providers](/cluster-secrets/). | `local` |
| `SB_SECRET_AWS_KMS_KEY_ID` | The AWS KMS key used to wrap each secret's key. Required with `awskms`. | Empty |
| `SB_SECRET_RECIPIENT_BACKUP_COUNT` | How many nodes besides the owner can open each sealed secret for `failover.policy=recreate`. At least 1 in a cluster, at least 2 in enterprise mode. | `2` |
| `SB_SECRET_FANOUT_MIN_ACK_WAIT` | How long a create waits for the first backup to confirm its copy. Must be above zero in a cluster. | `2s` |

## GPU support

GPU passthrough lets a sandbox use a physical NVIDIA or AMD GPU on its worker. The cluster sends GPU sandboxes only to nodes with a matching GPU.

To add GPU support, set `with_nvidia_gpu = true` or `with_amd_gpu = true` on a worker in `terraform.tfvars`. Terraform then passes `--with-nvidia-gpu` or `--with-amd-gpu` to the node's install script. The script installs the GPU tools and sets up Docker to use them.

There is no extra setting to add. Each node shares its GPUs over gossip, next to its CPU and memory.

- **NVIDIA:** installs the NVIDIA Container Toolkit. Needs an EC2 instance with a real NVIDIA GPU (`g4dn`, `g5`, `p3` and so on). The NVIDIA driver must already be installed.
- **AMD:** installs ROCm, AMD's GPU software. Works on `x86_64` instances only (`g4ad` and so on).

A sandbox can use a GPU or gVisor, but not both.

## gVisor

gVisor puts a small kernel of its own between each container and the server. That is a stronger wall than a plain container, and it needs no bare-metal hardware. It works on any EC2 instance type.

To add it, set `with_gvisor = true` on a worker in `terraform.tfvars`. Terraform passes `--with-gvisor` to the node's install script. The script installs gVisor's `runsc` runtime (the program that runs gVisor containers) and sets up Docker to offer it.

The node then tells the cluster it supports `gvisor`. The cluster sends `runtime: "gvisor"` sandboxes only to such nodes. There is no extra setting to add.

## Firecracker settings

Terraform writes these when a node has `with_firecracker = true` in `terraform.tfvars`. Firecracker runs each sandbox in a microVM (a small, fast virtual machine).

### Core settings

| Variable | What it does | Default |
|---|---|---|
| `SB_ENABLE_FIRECRACKER` | Set to `true` to turn on Firecracker on this node. | `false` |
| `SB_FIRECRACKER_BINARY` | Where the `firecracker` program is. | `/usr/local/bin/firecracker` |
| `SB_JAILER_BINARY` | Where the `jailer` program is. The jailer locks each microVM in for extra safety. | `/usr/local/bin/jailer` |
| `SB_FIRECRACKER_KERNEL` | Where the Linux kernel file (`vmlinux`) for microVMs is. Firecracker cannot start without it. | `/var/lib/sandboxd/firecracker/vmlinux` |
| `SB_FIRECRACKER_USE_JAILER` | `true` runs each microVM inside the jailer. | `true` |
| `SB_FIRECRACKER_RUN_DIR` | Where Firecracker keeps each microVM's socket files and state. | `/run/sandboxd/firecracker` |
| `SB_FIRECRACKER_TEMPLATES_DIR` | Where Firecracker templates are stored on disk. | `/var/lib/sandboxd/firecracker/templates` |
| `SB_FIRECRACKER_TAP_BASE_CIDR` | The IP address range for the virtual network cards that link microVMs to the server. | `172.16.0.0/20` |
| `SB_FIRECRACKER_TAP_POOL_SIZE` | How many of those virtual network cards to set aside. | `256` |

### Warm microVM pool

The pool keeps spare microVMs ready ahead of time. It refills itself in the background. It is off by default.

| Variable | What it does | Default |
|---|---|---|
| `SB_FIRECRACKER_VMM_POOL_ENABLED` | Turn on the pool. | `false` |
| `SB_FIRECRACKER_VMM_POOL_DEPTH_DEFAULT` | How many spare microVMs to keep for each template. Raise it for bursty work. | `0` |
| `SB_FIRECRACKER_VMM_POOL_REFILL_INTERVAL` | How often the pool checks itself and starts replacements. | `5s` |
| `SB_FIRECRACKER_VMM_POOL_GC_INTERVAL` | How often old spare microVMs are cleaned up. | `5m` |
| `SB_FIRECRACKER_VMM_POOL_GC_TTL` | How old a spare microVM can get before it is replaced. | `1h` |

### Template and snapshot settings

| Variable | What it does | Default |
|---|---|---|
| `SB_FIRECRACKER_SNAPSHOT_ENABLED` | Start microVMs from a snapshot. A snapshot saves a booted microVM's memory, so later starts skip the boot. | `true` |
| `SB_FIRECRACKER_TEMPLATE_MEMORY_MB` | Memory, in MB, for the microVM that builds a template. | `512` |
| `SB_FIRECRACKER_TEMPLATE_VCPU` | Virtual CPUs for the microVM that builds a template. | `1` |
| `SB_FIRECRACKER_TEMPLATE_BUILD_TIMEOUT` | The longest a template build may take. | `45m` |
| `SB_FIRECRACKER_TEMPLATE_GC_ENABLED` | Delete unused templates from disk on a schedule. | `true` |
| `SB_FIRECRACKER_TEMPLATE_GC_TTL` | How long a template can sit unused before it may be deleted. | `168h` (7 days) |
| `SB_FIRECRACKER_RSS_WATERMARK_RATIO` | The share of server memory to keep free. A new Firecracker sandbox is refused if it would push free memory below this. `0` turns the check off. A typical value is `0.10` (keep 10% free). | `0` |
