## Vision

### 10x Check
AerolVM becomes the one self-hosted sandbox that speaks every rival's API
(Daytona, E2B, Runloop today; agent-sandbox's later through the Kubernetes
effort) on one data model, so switching to AerolVM is a config change. Inside
this plan, the 2x lever that keeps that promise honest is the facade route
inventory test (X2): no facade can forward to a toolboxd route that does not
exist.

Design decisions taken during the spec review loop (all founder answers, 2026-11-05 and 2026-11-06):
- R1 (D8): buffered `exec` returns shortly after the command itself ends; background jobs keep running with later output drained and dropped; timeout kills the whole process group; `exec-streaming.mdx:540` rewritten; tests also on gVisor.
- R2 (D9): F1 and F5 go through the existing `/v1/sandboxes/{id}/toolbox/` pass-through with one toolboxd handler set shared with the Daytona facade; no new `/v1` file routes.
- R4 (D12): file calls use the SDKs' two existing retry tiers, as `exec` does, plus a rule that a retried delete or mkdir finding the work done counts as success; streamed bodies are never retried; no idempotency ledger. S4 `get_or_create` reuses the CLI's create-by-name, so a caller that loses a race reads the winner.
- R5 (D13): `lsp/*` returns a clear 501 from toolboxd; docs line changes from 404 to 501.
- R8 (D16): file watching (F5) only on gVisor and Firecracker; Docker and containerd return 501 (accepted shortcut, 7/10).
- R9 (D17): `aerolvm cp -r` download unpacks the tar with every entry checked.
- R10 (D18): new item O4 in Phase 0, counting toolbox calls by feature, result and API.
- R11 (D19): E8 limits Daytona terminals per sandbox and frees finished terminals' buffers.
- R7 (D14): build Daytona terminals as E8 (see Scope Decisions row 8); B1 returns 501 for `process/pty` until E8 lands. Spec review round 3 showed the TTY exec stream named in the D14 option kills on disconnect and keeps no list by id, so E8 is now built on toolboxd sessions (ids, reattach, resize, signals already exist). Same behaviour for users; flagged for founder approval at 0H.
